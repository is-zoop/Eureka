# 通用问题澄清

常规设置中的“问题澄清”默认关闭，仅控制日常对话。偏好保存在本设备浏览器中，同窗口和其他标签页同步；修改从下一条提交生效，不中断已经运行或等待回答的任务。插件声明与计划模式不受此开关影响。日常和插件仍遵守会话工具权限，完全禁用工具不会因声明或开关自动恢复工具。

宿主只有一个 `request_user_input` 工具。每次调用接受 1–4 个问题，每题 2–4 个真实可用选项，可单选、多选、自定义回答或跳过。助手先利用已有上下文，只在缺失信息会明显影响结果时提问。跳过不构成业务口径确认。

## 会话和接口

消息提交新增可选布尔字段 `clarificationEnabled`，旧客户端不传时为关闭。服务端根据每条已接纳消息的偏好、实际插件选择和所属 Skill 路径决定开放范围，不解析普通文本中的插件名称作为授权。插件仅安装但未通过入口调用时，不会开放日常澄清。插件归属包括 Haze 来源、能力 ID 和已加载包摘要，并在继续时重新检查身份、启用状态和版本。

提问后，工具返回 `terminate: true`，宿主在工具调用钩子及 Agent 的 `shouldStopAfterTurn` 边界阻止继续执行。等待期间没有悬挂的工具 Promise、模型请求或长期 HTTP 请求。外部排队消息由宿主保存偏好、插件选择和附件；插入消息在当前工具轮结束后接入，跟进消息在当前任务结束后接入。等待澄清时两者均暂停。

`POST /api/agent/:id` 支持：

- `get_clarification`：读取状态。
- `answer_clarification`：提交 `{ groupId, responses }`，每项为 `{ questionId, optionIds? , customAnswer?, skipped? }`；回答校验、保存后继续原任务。
- `retry_clarification`：对已保存答案但未成功继续的问题组显式重试，传 `groupId`。
- `cancel_clarification`：取消待回答或待重试的问题组，传 `groupId`；不自动发起查询。

问题组 ID 同时是继续执行的幂等标识。重复提交同一答案或运行中的重试不会重复启动；已提交的答案不能被另一份答案覆盖。失败后保留答案，重复发送答案不会隐式重试。服务端重建时将未完成的继续标记为中断，需用户明确重试，不自动重复可能已执行的远端查询。

状态保存在当前分支的 `eureka_clarification` 自定义记录中，并通过 `clarification_state` SSE 事件、运行状态及历史接口提供。状态包括问题组、答案、继续状态及未消费队列。历史回放不执行查询；取消时已经排队的请求保留并暂停，需从队列取回后明确重发，不会因取消或后来发送另一条消息而自动执行旧查询。后来新提交的请求仍正常处理。旧 `eureka_plan` 的问题仍通过兼容组件显示和回答，不迁移或改写旧记录。

## Atlas 插件修改说明

请将以下要求交给 Atlas 项目的 Codex 执行，仅修改 Eureka 版插件产物：

1. 在 `plugin.json` 的 `extensions.com.eureka` 中合并下列字段，保留 `schemaVersion: 1`、图标、认证等现有配置：

   ```json
   "capabilities": {
     "requestUserInput": true
   }
   ```

2. 修改 `atlas-ask` Skill：先读取适用规则和已有业务会话、语义口径。只有时间范围、指标定义、店铺范围或分析维度缺失且会显著改变结果时，才调用宿主 `request_user_input`。不要每次查询都提问，不编造指标、店铺或选项。
3. 工具调用示例：

   ```json
   {
     "questions": [{
       "title": "时间范围",
       "question": "本次流量分析使用哪个时间范围？",
       "selection": "single",
       "options": [
         { "id": "yesterday", "label": "昨天", "description": "查询上一完整自然日" },
         { "id": "last_7_days", "label": "最近 7 天", "description": "查询过去七个完整自然日" }
       ]
     }]
   }
   ```

4. 提问成功后等待宿主继续，不再输出一组普通文字问题、不调用查询工具，也不要求用户另开浏览器。用户可填写自定义答案或跳过；关键口径仍缺失时不得把跳过解释成同意默认值。
5. 回答后复用原 Atlas `session_id`、`scope_revision` 及选数状态。不得仅因澄清发生就新建业务会话或清空选数。`atlas-menu` 继续使用既有目录页面，选表不改成问答卡片。
6. 这是 **Eureka 宿主工具**，不在 `mcp.json` 注册，不在 Atlas 服务端新增同名 MCP 工具，不引入 JS、hooks 或读取宿主凭证的脚本。宿主没有提供工具时，退回普通文字询问必要信息，不声称已经展示卡片。
7. 更新插件宿主说明，说明 Eureka 已支持声明该能力；保留其他真实限制。同步提升 `plugin.json`、`package.json` 及 Haze 发布版本，然后更新安装；活动会话需显式重载。

安装准备和详情会显示“宿主能力 · 问题澄清”。未声明的旧包继续安装使用，但日常开关关闭时不会获得这项宿主能力。真实 Atlas 新包尚需验证“入口调用 → 歧义澄清 → 原业务会话继续查询”；离线包与模拟模型测试不替代真实联调。
