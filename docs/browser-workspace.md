## 查询工具生成与运行（M05-F1/F2/F3，待用户编译测试）

创建页新增“生成并运行工具”。基于当前草稿已保存、同编号校验通过的 M04 证据，服务器重新计算通过结论并生成 `browser-query-v1` 配置；当前界面通过证据可在生成时自动保存。每个创建草稿暂存一个工具，支持命名、重新生成递增版本、刷新恢复和最近一次运行。完整工具库及文件输入/下载留在 M06。

`lib/automation-tool.ts` 定义工具、输入、行结果及证据编译；`app/api/automation/tool/route.ts` 提供生成/改名/运行记录接口；`lib/automation-tool-store.ts` 按 Haze 身份加锁、原子保存。只保存语义控件、网站来源与页面路径、接口指纹、商品行身份及数字字段，不保留旧请求编号、活跃 DOM 引用、凭证或任意执行代码。首版只覆盖一个接口和同一商品对象中的字段，拒绝复杂多接口/嵌套列表及缺少商品身份的证据。

`components/AutomationTool.tsx` 接受 1～3 个不同的数字 ID 逐个执行，无需模型重新探索。`automation_browser.rs` 新增受控制令牌保护的 `tool-query` 固定动作；`tool-query.js` 唯一定位输入与查询按钮，先填写，再核对页面/输入并点击一次查询。沿用页面当前其他筛选，由网站处理登录、签名与跨源请求，没有服务端任意 HTTP 或脚本执行入口。

每个 ID 重建采集代次，取查询步骤中方法/来源/路径/接口指纹/编号匹配的唯一新响应，最多等待约 8 秒。`automation_tool.rs` 按真实商品 ID 读取字段，处理业务错误、缓存、身份不一致、字段缺失和截断；真零保留，缺少数字不补零。明确业务成功且结果数组为空才报告无结果。“已读取”不等于用户已核对新编号；同编号通过不证明任意输入正确。

暂停/隐藏/设置/环境变化使当前许可和采集代次失效，停止后续编号；异常停止，由用户显式重试。启动先保存运行中，结束写完成结果，刷新不自动续跑或把未结束记录当成功。记录仍为应用报告，不是独立认证证明。本轮补充测试源码，未运行编译、检查、测试或真实网站操作。编译命令与人工验收表见[路线图 v0.33](./automation-development-roadmap.md)。

## 网站探索与方法验证（M04-F1/F2/F3，待用户编译测试）

按用户最新要求，记录融入 AI 逐步操作：原生接管时自动开启记录，步骤派发后将相关请求关联到步骤和当前编号；AI 查询完成后停止记录并自动分析、复查同一编号。符合条件的请求直接复查；动态凭证、跨源或 POST 等限制改用已记录的网页查询动作，由网站重新发请求。正常界面取消手动录制、第二编号和人工勾选通过，展示执行模式、具体限制、字段比较表、结论、保存按钮及高级证据详情。原来的逐步动作核对方式保留。

原生 WebView2 在当前视图内订阅固定 Network 事件，不增加外部端口、不修改路由或缓存。自动记录最多 10 分钟/40 条，每个步骤的请求关联窗口最多 15 秒，原始 URL 在原生内存短暂保留。暂停停止采集；未进入校验且满足同一记录、同一页面身份/来源、有效账号/会话和时限时，继续恢复原记录及步骤。新一轮查询清空旧步骤，前后端按记录编号筛选历史；原记录查询后为零时提供“重新开始查询并记录”。没有本轮实际查询证据时不会用旧页面内容冒充验证，已有验证尝试不能借继续自动重试。

Cookie、密码及原始授权头不传给前端/模型；凭证和常见个人信息字段隐藏，未知字符串默认隐藏，保留有限结构、数字及成功/失败标志。开始操作前的说明会告知自动发送脱敏请求证据给所选模型；本轮证据可在高级详情查看，不增加一次人工预览确认。规则脱敏不是完整业务匿名化。模型没有工具，其候选请求及字段路径必须引用本轮实际证据，不能从省略响应推断业务字段。

针对用户实际报告的 `data.result` / `jsonBody` 字符串包装，先在本机尝试展开严格 JSON 对象/数组字符串，再逐字段脱敏；移除原先 120 字符门槛，仍受原始响应 64 KiB 限制。前后端同步最多 12 层/每对象 64 字段/数组 3 项；脱敏响应每条 24 KB、同记录合计 96 KB。字段路径枚举最多 512 条，优先数字业务指标和数据容器。截断目标字段/部分数组/预算省略都不能通过。响应类型说明只包含路径、编码类型和字节数，不含原始字符串；HTML/普通文本不执行、不直接发送，类型不支持时继续未通过。旧 `[string]` 内容不能通过重新分析恢复，需新编译后新采集。data/result/payload 对象包装层内的明确业务失败同样阻止通过。

针对实际表格中的 `managerPrice.currentPrice`、`managerQuantityNew.text` 和 `monthlySoldQuantity.value`，补齐明确价格字段的严格人民币单金额解析，以及紧邻业务父对象下的通用 text/value 数字叶节点。金额区间/HTML/未知格式仍不解析为单个数字，敏感字段仍先隐藏。数组有商品/SKU ID 时按 ID 对齐，重复/缺失身份拒绝；有商品 ID 时还核对查询输入的商品集合，多商品任务没有完整身份对应不能通过。比较表显示数值对应身份，并区分初次可读指标与已完成复查的指标。开发者未运行测试或网站查询，仍待用户编译验收。

直接请求模式使用原 URL 和全部原参数，不替换编号；固定网页内 fetch 保持当前登录，在浏览器创建的隔离执行环境中调用，单次复查使用 no-store，不更改全局缓存设置。规则允许的同源 GET 才执行，`api` / `method` 名称本身不再视作凭证，查询分发值经规则检查，写入/未知操作不直接复用。签名/凭证、跨源、非 GET 及操作未确认分别记录原因。

网页查询模式由原生重放此前人工核对执行过的明确查询动作，网站自行处理新签名、POST 和跨源请求；不会复制旧凭证或更改浏览器跨源规则。固定脚本保留同一页面的唯一数字编号输入框、查询按钮及当前可见筛选条件，DOM 引用与条件仅存网页内存，编号及动作说明进入脱敏报告。控件无法唯一对应或被遮挡、真实条件变化或页面身份变化时停止，不由模型临时扩大操作范围。整体只重复一次查询，最多关联四个必要接口的新响应；匹配方法、域名、路径、接口分发指纹、编号及查询步骤，最多等待约 6 秒，稳定约 1 秒后结算。没有唯一新响应、读取受限、缓存或 Service Worker 数据均不能通过；不把旧页面仍显示原值当作校验。

v0.31 补充：等价 DOM 重绘可按控件类型、名称/标签/占位说明在原区域重绑定；区域重建只在原来存活的祖先范围内唯一确认，不扩大到其他页面或使用模型选择器。真实编号/查询筛选保持一致，结果表格/行里的勾选等不作筛选；允许 ID/页码查询参数正常更新，其他页面身份条件保留。先准备并恢复按钮可见位置，再原生核对许可、开启新响应窗口并点击一次。准备不派发查询，实际执行仍重新核对条件；回车型查询复查改用唯一明确的查询提交按钮，避免双派发。停止原因分开固定显示并写入高级 JSON 的 validation.error；四项可读不代表已取得第二次响应，M04 仍待用户编译测试。

从停止记录、模型分析到请求比较结束均保留 AI 输入占用，结束或暂停才交还网站操作。暂停撤销原生许可并停止记录；未知派发结果关闭视图。两种模式不在失败后反复切换、自动重试查询。

比较基准是网页查询实际触发的接口响应，不是截图或 DOM 全文。模型只选择有证据的字段路径，Rust 与 TypeScript 确定性比较价格、库存、销量等所需数字；时间戳、请求 ID、状态码、隐藏值不参与。缺字段、结构/数组截断、错误响应或数值不一致均不能通过；对任务明确要求的指标检查完整覆盖。取消使用原生许可版本和前端运行代次同时作废，即便取消先于迟到校验调用到达也不能再派发查询；未完成的状态保存为未完成。

脱敏证据、自动分析与比较结果可显式保存到当前草稿，服务器按报告、原生比较状态及复查结果再计算结论，不仅接受前端通过标志；网页模式保存查询动作说明及新响应引用，不把旧 DOM 引用保存成可执行工具。文档仍不可执行，刷新只恢复保存摘要；M05 仍需生成工具。网页模式依托当前登录浏览器，两种通过都只表示本次相同输入返回一致，不表示已经证明跨编号泛化能力。开发者没有代查真实商品值。

模拟页为 `http://127.0.0.1:8080/automation-research-demo.html`，接口仅开发模式开放，数据明确为虚构。为独立 WebView 测试，只对这一个页面和这一个模拟接口在开发模式免 Haze Cookie；Host/Origin 校验仍保留，其他 API 认证不变。编译命令、模拟值与淘宝测试步骤见[路线图 M04 记录](./automation-development-roadmap.md)。本轮未运行编译、检查、测试或实际浏览器验证。

## 默认持久浏览器与可选独立环境（M03-F1/F2/F3 调整，待用户测试）

2026-10-30 按用户要求调整为普通浏览器体验：默认自动保存各网站登录，关闭网站或重启 Eureka 后继续使用；无需先创建账号。网站过期时人工重新登录，在网站内退出再登录即可换账号。AI 使用当前网站账号，开始前提醒核对店铺，取消强制账号确认按钮。

默认环境按 Haze 所有者摘要保存，跨网站和任务复用。高级选项提供独立环境和 InPrivate 临时会话；旧账号资料和绑定继续作为独立环境使用，不自动合并登录。草稿无账号引用/模式时使用默认环境；显式 `browserMode: temporary` 才使用临时模式。原生视图、复用、授权续期均包含模式身份。同环境使用 Windows 独占文件句柄，退出/崩溃后自动释放；目前单个原生网站视图按需切换环境。

可选“允许此浏览环境询问是否保存账号密码”，默认关闭；保存偏好后，原生 WebView2 的 `ICoreWebView2Settings4.SetIsPasswordAutosaveEnabled` 控制浏览器保存/更新提示。用户可拒绝，Eureka 不自行采集密码。关闭开关不删除既有密码，也不保证关闭其自动填写。“清除默认浏览器数据”会清理默认环境所有网站登录、密码和本机浏览数据；独立环境提供各自清理/删除。清理先更换环境代次再异步删除旧文件，被占用时显示待清理及重试。

不导出 Cookie、密码或浏览器资料路径，不将登录环境放入模型请求或插件。资料目录依赖 Windows 用户的文件访问边界，整个目录并非全量加密；Haze 分目录不是不同 OS 用户级别的隔离。开发测试版和正式版的数据目录不同，不自动迁移。网站自己的登录有效期仍生效。WebView2 持久化原理见 [Microsoft 用户数据目录说明](https://learn.microsoft.com/en-us/microsoft-edge/webview2/concepts/user-data-folder)。

## 使用

在输入框的添加菜单或 `/` 菜单中选择“插件”下的组织插件，例如“Atlas数据助手”。选择以标签显示，支持同时选择多个插件；输入业务请求后发送。选择只作用于当前消息，不等于安装、启用或新增工具权限。

普通 Pi 市场包仍在原有插件管理入口维护。组织插件的版本更新、停用、卸载及地址授权继续在组织扩展详情中操作。出现“待重载”、认证失效或技能冲突时，先处理详情中的状态并重载当前会话。

模型调用组织插件后，插件返回的选数链接会自动打开右侧网页面板，输入框不提供手动浏览器按钮。面板支持 HTTP/HTTPS 地址、标签页、前进后退、刷新、点击、滚动、键盘、中文输入和文本粘贴。网页使用 Eureka 服务端的网络环境：远程部署时 `localhost` 指服务器，不是使用者电脑。

“隐藏”暂停画面传输并暂留网页环境；无可见面板连接十分钟后清理。关闭浏览器会立即清理网页 Cookie 和存储。不同 Eureka 对话、不同账号使用独立环境；退出、账号切换或删除对话会释放对应资源。进程重启不恢复网页登录状态。

本期不提供模型网页操作工具，也不提供自定义 `/atlas-menu` 命令、文件上传下载、网页对话框交互、系统剪贴板读取或持久浏览器配置。浏览器自动化可后续在同一运行时上增加，不应另建一套网页登录环境。

### 跨运行保留登录（v0.67）

编译反馈修正：用户构建报告 E0432，新休眠视图分支把 `EnableWindow` 错引到 `WindowsAndMessaging`。已按本地 windows-sys 0.61.2 声明改为 `UI::Input::KeyboardAndMouse::EnableWindow`，与现有输入门控引用保持一致；不需要新增依赖或功能开关。未主动编译或测试，用户重新执行同一编译命令。

用户反馈第二次运行仍需登录。源码确认默认／独立环境已使用固定 `data_directory` 且非 InPrivate，但 `applicationRunId` 变化会重挂载 NativeBrowserPanel，旧组件清理执行 close；原实现每次销毁 WebView，仅保留磁盘资料。现在 close、普通页面刷新及 30 秒任务租约到期会撤销控制令牌、清空任务 ID、隐藏并禁用持久环境的原生视图，保留浏览器本身持有的会话 Cookie。再次打开时按 Eureka 用户、环境 ID、资料代次匹配，重新绑定任务并导航至声明入口；不同运行使用不同的 native session ID，旧 close/pause 无法命中新运行。不同环境分别保留，切换 Eureka 用户会销毁其他用户的缓存视图。临时环境仍关闭清理，应用退出仍完整释放全部视图。

本轮不提取或复制 Cookie，不改 Cookie 到期时间，不向模型／插件传递凭证，不使用实验浏览器启动参数。磁盘持久 Cookie 沿用 WebView2 的固定资料目录；仅会话 Cookie 的内存保留限于本次 Eureka 进程，不能据此承诺所有网站在完整退出 Eureka 后仍登录。微软的 [Cookie API](https://learn.microsoft.com/en-us/microsoft-edge/webview2/reference/win32/icorewebview2cookie) 区分会话和持久 Cookie；站点服务端仍可使登录失效。首次连接增加最多约 5 秒的只读页面／账号标记等待，减少 SPA 尚未恢复登录就请求人工登录的误判；不重试网页变更。

持久视图保留原有跨进程资料锁；管理页只把本进程已释放任务的环境显示为可管理，其他进程占用仍报 busy。修改环境名称／网站元数据、密码保存及旧代次清理可在已持有锁下完成，不销毁当前登录；显式清除登录／删除环境销毁对应休眠视图并旋转代次，不能从缓存复活旧登录。

未运行编译、测试或真实网页验证。需用户退出 Eureka 并按本文原生编译命令重编译，然后重启本地服务（使服务端运行 ID 与等待逻辑生效）。人工验收：

1. 配置选择“默认浏览器（保留登录）”或同一自定义环境；首次登录并完成一次自动化，使用相同环境再运行，应直接复用网站登录。
2. 关闭网站面板，等待超过 30 秒，再运行；或刷新 Eureka 页面再运行，应仍复用同一浏览器会话。更换查询参数不会沿用旧任务／动作。
3. 切换两个自定义环境，各自登录后再切回，不能串用账号；修改名称／密码保存选项后仍保留该环境登录。
4. 手动在网站退出登录，或在设置清除登录，下一次应正常要求登录；临时环境关闭后重新运行也应要求登录。
5. 完全退出再启动 Eureka，单独记录站点的登录是否保留，用来区分磁盘持久登录和仅进程内会话，不能把进程内第二次运行通过当作这一项通过。

桌面版使用 `desktop/src-tauri/src/automation_browser.rs` 创建原生子 WebView，在 Windows 上由 WebView2 直接绘制网页和处理输入。`NativeBrowserPanel` 只同步侧栏位置、大小、地址、标题和生命周期，不使用 canvas、画面 SSE 或键鼠转发。此模式不启动外部 Chrome。`POST /api/automation/browser` 收到 `presentation: "native"` 后，核对身份及保存草稿，返回网站视图描述并关闭该草稿旧的转发 Chrome；目标地址只来自服务端草稿。

默认和独立环境使用各自常规资料目录；显式临时模式使用独立临时目录和 InPrivate，两者均与 Eureka 主界面及日常浏览器隔离。只有 `eureka-content` 的本机界面获得管理命令权限，业务网页子视图没有宿主命令权限。前端每 5 秒核对当前草稿所有者、环境和模式，身份不符或验证失败请求停止当前任务；桌面端授权续期中断超过 30 秒同样撤销任务。v0.67 起默认和独立环境在任务结束后隐藏禁用并保留原生会话，临时模式仍关闭清理；不能用旧任务身份读取休眠视图。显示位置会换算应用缩放和标题栏偏移；v0.64 起菜单及弹窗不再隐藏整个网站视图，而通过原生窗口区域为实际覆盖的弹层让出绘制和点击位置。

原生视图支持单网站、原生输入、前进后退、刷新、导航、隐藏和关闭。HTTP(S) 弹出链接暂时转到同一视图；依赖 `window.opener` 的复杂登录弹窗仍需后续适配，不能声称完整多标签支持。下载暂未开放。隐藏、关闭面板、完整刷新或切换任务保留持久环境的原生会话；完整退出后仅保留浏览器持久化到磁盘的数据，网站的仅会话登录不保证跨进程。临时模式清理登录并尝试删除目录。M02 AI 单步和暂停接管已通过用户验收，M03 新持久化方案待用户复测。

### 网页版转发面板（保留的兼容路径）

`lib/browser-window-launcher.ts` 直接启动配套 Chromium，使用随机独立临时资料目录和预分配的本机明确调试端口，再通过 connectOverCDP 连接默认上下文。浏览器默认最小化；面板通过 CDP 获取网页画面并转发输入，并非原生窗口嵌套，因而有编码、请求排队和解码延时。系统任务栏可能仍显示 Chrome；本轮去掉了内置模式中不必要的窗口置前调用。不同会话使用独立进程；正常关闭或启动失败会关闭该进程并清理专用目录，崩溃或断电不能保证清理。

`POST /api/automation/browser` 使用 `presentation: "embedded"`。与组织插件面板不同，自动化的两种显示模式都保持直接启动、默认网络及缓存，不安装全站请求路由。通过 Eureka 打开或跳转的地址仍校验 HTTP/HTTPS，真实窗口原生导航遵守浏览器自身安全规则。

“弹出窗口”（`show-window`）切到 `presentation: "window"`，停止画面与键鼠转发、清除面板尺寸覆盖，恢复真实窗口供直接操作。“返回内置浏览器”（`show-panel`）恢复内置画面与输入，并将窗口最小化。两种模式复用同一进程、页面和 Cookie；打开已有草稿也会复用已打开的窗口。更旧的 Playwright 启动会话升级时才需重建并重新登录。

新页面自动登记，关闭最后一个页面清理会话。隐藏面板停止画面传输，但自动化浏览器不因隐藏而执行十分钟清理；身份变化仍关闭浏览器，关闭和进程重启不保留登录状态。普通组织插件浏览器保留原来的启动方式及生命周期。

本轮面向本机桌面部署。2026-10-29 用户确认明确端口的真实窗口版本可以登录淘宝，且当次未出现验证码；内置面板的新输入路径仍待用户复测。不包含验证码自动处理或浏览器身份伪装。

- 白块：Base UI Popup／Backdrop 可在关闭后仍挂载，且 `[hidden]` 的默认样式可能被作者 CSS 覆盖。检测首先排除自身或祖先的 `hidden`／`data-closed`／`data-state=closed`，公共 Dialog 对关闭态显式隐藏；不把仅用于读屏隔离的 `aria-hidden`／`inert` 当作视觉隐藏。恢复使用完整客户区 region，并请求网页子树重新绘制；最后一个让位弹层关闭时重新呈现原 WebView2 合成表面，不导航／刷新网页。已打开视图的显示同步失败可退避重试，避免一次失败永久冻结旧孔洞；不重试网页业务动作。
- 登录：原 `probe` 只判断 origin/path 和可选账号字段，同址登录表单或未声明账号字段的只读应用可能绕过询问。固定 DOM 探测增加可见密码／一次性验证码控件、登录或验证 iframe／对话框及登录 URL 的布尔信号；不读取输入值、不返回凭证。初次连接仍只读等待约 5 秒，未就绪或需要验证时释放控制并调用已有 `askLogin`／UserInputCard；有效登录直接继续。等待超时不再直接终止而漏掉卡片，停止、断连与授权错误不会转成自动重试。补同址登录、无账号字段及有效页面不重复询问的回归测试源码，未执行。

需用户重启开发服务、退出 Eureka 后执行下方原生编译命令。验收：配置弹窗打开时包括网站自有活动弹窗在内的整个网页变暗且禁用；关闭 Eureka 弹窗后没有白色孔洞、宿主遮罩消失、网页恢复操作，连续开关及窗口尺寸变化仍正常。网站自己的活动弹窗及其遮罩属于网站状态，仍由网站关闭按钮处理，不随 Eureka 配置弹窗一起删除。临时环境中主动退出网站后再连接应出现登录卡片；登录成功后下一次运行应直接复用，同一网址内的登录框也应暂停询问。

v0.66 统一模态弹窗的背景：用户反馈网页保留亮色会造成视觉混淆。前端读取共享 Dialog 遮罩的实际透明度（含深色主题及多层遮罩叠加），通过 `dimAlpha` 传给原生层；Windows 在网站子窗口内放置黑色半透明、禁用且不抢焦点的子遮罩，并继承现有弹窗让位区域。弹窗本体不变暗，网站画面保持实时显示但不可操作；普通下拉菜单不添加整页暗化。关闭模态弹窗销毁遮罩，网站关闭时由父窗口一并销毁，不保存截图、不修改网站 DOM 或样式。输入仍由既有 UI／AI 合并门控管理，关闭弹窗不会续跑 AI。需重新编译；未主动编译或测试。人工验证浅／深色主题下配置、运行记录等弹窗的网页背景与周围一致变暗、弹窗可点击、关闭后恢复，以及下拉菜单、调整窗口和隐藏／重开浏览器不留遮罩。

v0.65 修正弹窗后的灰色外框：移除让位区域四周的 4 CSS 像素扩边，使用弹窗实际边界及统一圆角半径生成原生区域。弹窗跨越网页槽位时保留原始坐标，由原生区域相减裁切，避免槽位边缘出现额外圆角。网页输入锁及关闭后恢复逻辑不变。该调整涉及前端与 Rust，需退出 Eureka 后按下方命令重新编译；未主动编译或测试。人工检查配置弹窗四边与圆角无额外灰框，按钮可点击，关闭后网页显示完整；缩放菜单和调整分隔线时同样检查。

取消“出现菜单即 hide”的逻辑。前端只发送宿主弹层与网站槽位相交的局部矩形；左侧菜单不相交时不影响网站显示。`browser_overlay.rs` 在 Wry 网站子窗口上使用 `SetWindowRgn`／`RGN_DIFF` 为弹层覆盖位置让出区域，区域同时影响绘制与点击，按钮由底层 Eureka 内容 WebView 接收点击；未覆盖的网页保持实时原生绘制。菜单关闭后恢复完整窗口区域，不重载网站，也不读取或转发截图。

公共 Dialog 的 backdrop 标记“模态阻止交互”，并从 v0.66 起同步原生网页暗化透明度，不将整个遮罩作为裁切区域；只有弹窗实际矩形让位。打开模态弹窗或覆盖网页的菜单时，`ui_blocked` 与 AI 接管状态共同决定原生网页输入开关，避免点击穿透及暂停操作后误解锁；开始阻止交互时立即撤销旧控制令牌，状态转换使旧观察引用失效。关闭弹层只恢复允许的人工输入，不自动继续已暂停的 AI 步骤。所有原生操作只作用于验证过的 Wry 子窗口，不能操作 Eureka 主窗口。

原生窗口区域由 Windows 管理，使用后不重复释放；计算换算包含 Windows DPI 和 Eureka 缩放。只传宿主 UI 的坐标与阻止交互标记，不包含网页内容、账号或 Cookie。面板主动隐藏／离开工作区时仍沿用原有 hide／close 生命周期。此实现适用于当前 Windows 桌面版，需用户重新编译；本轮未编译、测试或实际 UI 验证。

## 接口与插件链接契约

- `GET /api/organization-extensions/composer?cwd=...&sessionId=...`：当前来源的有效组织插件及状态，遵守项目覆盖全局和项目信任。
- 消息提交可携带 `selectedPlugins`：来源、能力 ID、包摘要及展示名称。服务端重新解析并校验，客户端名称不决定实际加载对象。上下文记录随消息保存，输入框、历史显示及恢复隐藏内部展开文本。
- `GET /api/browser?sessionId=...`：浏览器摘要及 Chromium 就绪状态。
- `POST /api/browser`：打开、新建/选择/关闭标签、导航、返回、前进、刷新、调整 viewport、鼠标、键盘、文本及关闭浏览器。
- `GET /api/browser/events?sessionId=...&frames=1`：SSE 状态与 JPEG 画面。`frames=0` 仅订阅插件打开通知，不保活或传输画面。API 需要当前 Haze 登录，访客不可用。

宿主仅处理当前会话已登记组织 MCP 的成功工具结果。实际服务器身份来自 adapter 的结果详情，不根据聊天中的工具名或链接猜测。支持 MCP `structuredContent` 或文本块中的顶层 JSON 对象，以及 Atlas 标准 `{ data: { browser_url, ... }, request_id }` 响应信封。接管后保留原有信封、业务字段与请求编号，移除启动链接并加入 `browser_panel`：

```json
{
  "session_id": "当前业务会话",
  "scope_revision": 3,
  "browser_url": "https://atlas.example/selector#launch=短期启动凭据"
}
```

Eureka 消费 `browser_url`，在当前对话右侧打开顶层网页；同一插件、业务会话复用标签。成功交接后，工具结果保留业务字段并返回 `browser_panel` 状态，模型无需再次打开系统浏览器。失败时明确返回失败，检查运行时或目标服务后重新调用原工具获取新链接。历史消息回放不会重开页面。

短期启动地址不写入宿主日志、草稿或持久浏览器状态，画面和 URL 仅对所属用户可用。地址栏摘要不显示 query 或 fragment；宿主不向网页注入 Haze、Eureka Cookie 或个人凭证。网页以真实 Chromium 顶层页面加载，不通过 iframe 或改写目标站点安全策略。
