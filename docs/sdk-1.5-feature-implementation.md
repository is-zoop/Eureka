## 使用与生效范围

- **命令环境**：「设置 → 通用 → 命令环境」。默认 Bash；PowerShell 仅在原生 Windows 可选。只影响新会话的模型命令工具；手动 `!` / `!!` 命令继续使用既有 Bash 链路。配置保存在 agent 目录的 `eureka-command-environment.json`，不覆盖 SDK 的其他配置。
- **MCP**：手动服务器编辑页、组织独立 MCP 的既有配置对话框提供工具暴露选项。保存后新会话或显式重载生效，不中断当前运行。组织插件内部的服务器没有新增配置入口，保持插件原有行为。
- **MCP 界面清理**：工具提供方式改为带简短说明的单选列表，复用原生命周期行样式；生命周期、空闲断开控件与其前端校验已移除。原生 SDK 管理连接，新界面只提交工具暴露方式；后端兼容旧请求并保留已保存的旧字段，不迁移历史配置。

该界面调整已通过 42 项相关回归、类型检查和修改文件 lint；回归包含只更新暴露方式时保留旧字段，以及 Haze 认证与原生 MCP 调用。此结果单独记录，不替代下文前一轮全量检查的结果。
- **等待用户**：复用原进度文案；不新增聊天区域。历史活跃时长排除宿主记录的等待区间，工具本身的墙钟耗时仍保留真实经过时间。服务器重启无法恢复的 SDK 对话不会被当作持续等待。
- **模型与费用**：用户认为当前信息重复，已移除消息底部及处理详情中的独立弹层入口；不新增其他详情入口，原模型名、token 用量和总金额保持原展示。底层仍兼容 SDK 的实际响应模型及费用来源元数据。
- **分类模型**：自动化应用配置中的业务 AI 增加独立选择器；默认未启用。仅影响明确声明 `operation: "classify"` 的规则，未配置、模型不可用或结果无效时明确失败，不回退聊天模型。推理强度和输出 token 上限仍用于原聊天 AI，分类沿用应用超时、图片授权、运行次数和取消限制。

## 分类规则示例

### 生成失败修复记录

2026-11-16 实际生成中发现：生成器读取的 `ai` 章节仍以聊天 AI 为主，没有给出独立分类的完整模板，模型把 `type` / `criteria` 写在规则根部，或将 `output.type` 写成 bool/choice，导致写入前的包结构校验反复失败。

已补齐模型实际读取的 SDK 章节（bool/choice/score 三份完整 JSON、字段位置和结果包装示例），并同步生成仓库手册。校验错误现在包含文件名、规则 ID 和预期字段/类型；写入失败摘要直接显示错误，保留原行布局。回归使用真实注册的写入工具和保存流程，未执行应用或调用计费模型。有效规则和旧聊天 AI 的契约保持不变，不通过放宽校验来接纳猜测格式。

既有运行可能持有旧版宿主扩展，更新服务/桌面版本并重启后，在原任务重新读取 `eureka_automation_task {sdkSection:"ai"}`，再按正确模板继续生成。已有保存规则不做自动改写。

仍使用现有 `ctx.ai(ruleId, input, { images? })`，并位于声明的 `kind: "ai"` 节点中；无需新增脚本方法。

```json
{
  "schemaVersion": 1,
  "rules": {
    "eligible": {
      "operation": "classify",
      "instruction": "判断输入商品是否符合上架条件。",
      "output": { "type": "boolean" },
      "classifier": {
        "type": "bool",
        "criteria": { "true": "符合", "false": "不符合" }
      }
    }
  }
}
```

`bool` 返回概率大于等于 0.5 的布尔判断；`choice` 的 criteria 为标签到说明的对象，返回标签字符串；`score` 的 criteria 为从低到高的等级说明数组，返回 0 至等级数减 1 的期望等级索引。输出类型分别声明为 boolean / text / number，宿主继续校验 output。模型调用、用量（服务商提供时）及节点关联保存在当前运行记录；不会保存模型凭证。

## N07：对话生成图片首版

用户确认入口改为普通对话中的直接请求，不添加输入栏按钮或生成弹窗。

### 使用方式

1. 更新并重启 Eureka，使用新对话；工具权限需为默认或完整，不能为关闭或只读，也不能处于计划或自动化创建模式。
2. 在设置 → 模型配置支持图片生成的服务商。当前安装的 SDK 内置图片适配器为 OpenRouter；已安装全局扩展也可以提供 image 类型模型。主聊天模型继续使用原来的 GPT-6.1 Sol 等模型，不需要切换。
3. 发送“帮我生成一张图片：一只坐在窗边的橘猫，柔和日光”。可以在请求中写明希望使用的可用图片模型。模型从当轮提供的独立 image 模型目录选择，不把聊天模型当作图片模型。
4. 成功后在对话中直接看到图片卡片，点击图片可放大，点击“保存图片”选择保存位置。卡片在处理详情折叠后仍可见；重新打开会话后按已保存图片 ID 恢复。
5. 没有可用图片模型时，聊天模型会提示配置图片服务商。现有聊天或 Codex 订阅登录能否调用图片 API 不能由聊天可用性推断。

### 开发边界

- 仅明确的用户图片生成请求启用 `eureka_generate_image`，普通聊天、引用说明、否定请求、宿主 custom 消息不启用。模型解释“如何生成图片”不应产生生成请求。开头表达未被识别时，可使用上面的明确句式。
- 每次用户运行最多一个生成尝试；`maxRetries: 0`，数量请求固定为一张，结果必须恰好包含一个图片块。失败后本工具不会自动重试、回退聊天模型或切换服务商。用户再次明确发起请求才构成新的尝试。
- 取消、超时或失效身份不会继续写入完成产物；同一工作区同时只允许一个图片生成任务。生成请求不通过浏览器端 SDK 或直接提取 API Key 调用，沿用宿主 ModelRuntime 的服务商认证。
- 不修改聊天默认模型、权限预设、原自动化 AI/分类规则、MCP/Haze 认证或已关闭的 N10/N13。没有增加 Agent 的自动批量生成、图片编辑、自动化节点或 Codemode 模型桥接。
- 只接收 PNG/JPEG/WebP 的有界 base64 结果，校验类型、文件签名和大小；不读取返回的远程 URL，不允许 SVG/HTML。每张最多 20 MiB，本地空间预留限制为 512 MiB，最多 200 条任务记录；达到上限时拒绝新任务，不静默删除用户图片。
- 图片及描述/模型/用量元数据保存在 agent 目录 `generated-images/<本地工作区 ownerKey>/`，使用 UUID 文件名。真实路径检查拒绝目录链接和路径穿越，不把该目录加入通用文件浏览授权。
- 会话只记录图片 ID 和安全结果摘要，不存图片 base64、SDK 凭证、原始上游错误或响应正文。图片描述作为本地产物元数据保存。费用区分服务商报告与 SDK 估算；未报告/无可靠金额时不显示为免费。图片费用暂不并入主聊天的消息费用，避免重复计费展示。
- 仅授权 GET 接口用于目录、元数据和图片读取；不提供不受对话运行限制的生成 POST。保存复用现有 `saveFileAs()`，取消另存为保持静默。
