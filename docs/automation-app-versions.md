# 自动化应用版本

个人应用通过“AI 修改”修改已保存代码时，宿主自动递增 patch 版本，例如 `1.0.0 → 1.0.1`。同一轮未保存草稿的后续编辑保持当前版本；保存后，下一轮修改再递增。显式声明了更高版本时保留该版本。

版本号会同时写入 `plugin.json` 与 `package.json`，重新校验并计算摘要。保存发布包使用不可变安装入口，追加版本登记并保留旧代码，不覆盖同版本内容。保存重试和中断恢复通过候选摘要、保存意图和登记修订号确认已提交的版本，不重复创建版本。

自动化目录默认使用最新版本。在应用菜单“查看详情”下方选择“选择版本”，可以切换当前应用的历史版本。应用标题后显示实际打开的版本号。切换是当前视图的选择，不修改目录的默认版本；重新打开应用回到最新版本。运行期间不能切换版本。

详情、运行和浏览器配置请求携带版本号。请求内的 store 视图在原登记锁下校验修订号并读取所选版本的不可变代码，不通过修改全局 activeVersion 实现切换。运行记录固定版本及 digest；重复的运行 ID 不能用于不同版本。历史版本的导出和 AI 修改使用所选代码；以历史版本为基础修改时，新版本号仍高于目录中的最新版本。

应用配置、业务文件、浏览器环境和登录态仍属于同一个应用，旧版本的文件授权会继续校验代码摘要。组织插件保持由安装来源选择有效版本，不提供个人应用的历史切换入口。
