## 1. 用户需求

网站入口：[淘宝卖家后台—出售中的宝贝](https://myseller.taobao.com/home.htm/SellManage/on_sale?current=1&pageSize=20&queryItemId=)。

查询以下商品的价格、库存、累计销量和 30 日销量：

```text
944311760187
978240175678
```

建议工具名称：**淘宝在售商品数据查询**。

这是首个验证通用框架的真实业务案例。网站、商品 ID 和字段由任务输入提供，不硬编码为 Eureka 唯一支持的自动化。

## 2. 首轮范围

- 用户在 Eureka 浏览器中登录自己的淘宝卖家账号。
- 在用户指定的在售商品页面查询两个商品。
- 读取四个目标字段，先形成可人工核对的结果表。
- 后续依路线图增加保存、重复运行、Excel 导出和 Haze 插件分发。
- 本轮不修改商品价格、库存、上下架状态，也不报名活动或提交其他业务写入。
- 不从其他店铺、买家详情页或其他账号补齐缺失数据；如需其他页面，应先明确业务口径与范围。

当前未检查用户的真实登录状态、店铺归属或商品是否在售。公开网页读取未成功，不能据此推断用户本机能否打开页面；这些项目留待浏览器阶段验证。

## 3. 字段口径与结果结构

第一版默认以指定页面中对应商品的实际显示为准。下列是验收约定，不是已观察到的页面字段或接口定义。

| 字段 | 首轮处理方式 |
| --- | --- |
| 商品 ID | 按文本保存并精确匹配，不转换成科学计数法 |
| 价格 | 保留页面原值及单位；显示区间时保留区间，不擅自取最低价、优惠价或某个 SKU 价格 |
| 库存 | 优先读取商品列表对应的库存字段；如只能获得 SKU 库存，先说明差异，不未经核对自行汇总 |
| 累计销量 | 读取页面明确对应累计销量的字段，保留原值和单位 |
| 30 日销量 | 读取页面明确对应近 30 日的销量；不能用自然月、付款人数、订单数或其他指标替代 |
| 查询时间 | 每次结果附北京时间，便于核对动态数据 |
| 查询状态 | 成功、部分字段缺失、未找到、登录失效或查询失败，并说明原因 |

页面显示 `--`、空白或没有该字段时，记录“未显示/无法确认”，不得填成 `0`。若显示“1万+”等简写，保留原始文本；没有可靠来源时不编造精确值。

四个目标字段都得到有效证据且口径一致，才算完整成功。查询得到部分字段时仍保留已获得的数据，并明确指出缺失项。

最终结果示意（占位符不是真实数据）：

| 商品 ID | 价格 | 库存 | 累计销量 | 30 日销量 | 查询时间 | 状态 |
| --- | --- | --- | --- | --- | --- | --- |
| 944311760187 | 待查询 | 待查询 | 待查询 | 待查询 | 待记录 | 未执行 |
| 978240175678 | 待查询 | 待查询 | 待查询 | 待查询 | 待记录 | 未执行 |

如果页面标签或实际指标与上述约定不一致，记录具体差异，再更新口径。技术上拿到数值不等于业务上查询正确。

## 4. 首次人工核对步骤

这部分在 M01 浏览器入口就绪后，由用户实际操作并核对；不要求用户现在提供密码或 Cookie。

1. 在 Eureka 打开指定网站，登录拥有相关商品权限的卖家账号。
2. 在页面选择正确店铺，使用商品 ID 查询第一个商品。
3. 核对商品 ID，观察价格、库存、累计销量、30 日销量是否可见，以及页面实际标签和单位。
4. 清除或替换查询条件，再查询第二个商品，检查结果没有残留为第一个商品。
5. 将页面值与工具结果按同一账号、同一口径、接近的时间核对。
6. 动态数据变化时重新查询对比；账号数据和截图留在本机测试位置，仓库文档只记录验收结论及脱敏问题。

样例输入可以先直接粘贴两行 ID，Excel 输入放在 M06-F2 实现，不作为 M01 的前置条件。
