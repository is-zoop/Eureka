#### 特殊 TypeBox 功能的迁移要求

SDK 1.5 按 JSON Schema 校验工具参数，不调用 TypeBox 私有回调。以下行为已用真实 SDK 调用路径验证：

| 旧定义或行为 | SDK 1.5 行为 | 插件处理方式 |
| --- | --- | --- |
| `Type.Refine()` | 不运行 refinement 回调 | 优先改用标准 JSON Schema 约束；无法表达的业务检查放入 `execute()`，在产生副作用前检查并抛出明确错误 |
| `Type.Codec()` | 不自动解码，工具收到 JSON 输入值 | 在 `execute()` 中显式转换并处理转换失败 |
| `Type.BigInt()`、`Type.Undefined()`、`Type.Void()` | 无法接收对应的 JSON 参数 | 改用 JSON 可表示的 schema；大整数可用字符串传输，可选参数使用 Optional 并省略字段 |
| TypeBox `Format.Set()` 自定义格式 | 不执行 TypeBox 格式回调；标准格式仍会校验 | 使用标准 format、pattern 或显式业务检查 |
| 依赖旧 TypeBox 错误文案 | 校验错误改为 pi-schema 的路径与说明 | 通过工具错误状态和明确字段定位问题，避免依赖旧错误文本 |
| MCP `strictDirectToolArguments` | 严格预处理先于 SDK 校验执行 | 保留严格模式的类型及额外字段限制，不因 SDK 的宽松转换而自动放宽 |

### C05 上下文编辑与历史恢复

- 状态：已完成。
- 实际问题：SDK 1.5 的 `context_edit` 可替换或省略较早消息的模型上下文贡献；旧读取器只取得原始条目，导致显示上下文与模型实际看到的内容不一致。SDK 也会在转录中保存系统提示及工具检查点。
- 修改结果：`session-reader.ts` 使用公开 `buildSessionProjection()`，应用编辑后再转换消息，保留原始条目 ID 与消息的一一对应。完整历史继续显示原始审计内容；系统检查点不生成聊天气泡。
- 用量修复：上下文编辑后不复用编辑前的模型报告 token 数；快照版本按编辑条目失效。系统检查点不再重复计入“消息”分类；实时快照使用 SDK 会话有效提示及宿主禁用工具策略。
- 验证：新增 4 项上下文编辑测试，覆盖替换、省略、自定义消息显示属性、兄弟分支与回退、压缩后检查点、文件重开及原始历史不变；新增用量失效测试与系统消息去重测试；禁用工具的真实 SDK 用量分类也验证为零。
- 边界：此项完成读取与恢复兼容，没有新增面向用户的上下文编辑按钮。
- 后续修复（同日，发送消息重复显示）：真实会话只有一条用户记录，但 SDK 在用户回传前发出 `system` 检查点，流式界面把它加入消息列表，打断本地消息与回传消息的相邻匹配。现在实时开始/结束事件先过滤非聊天记录；仅合并尚未确认的本地用户消息，连续同文提交和队列消息仍保留。
