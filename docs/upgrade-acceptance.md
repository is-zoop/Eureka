# Eureka 安装与升级验收

当前状态：验收准备，尚未执行真实安装或跨版本升级。GitHub 构建独立运行，当前不持续监控。

## 第一轮：首次安装 0.8.8

使用测试用的 Windows 用户或测试电脑。先结束正在运行的任务，再从托盘退出旧版 Eureka。
下载安装包时核对版本和 `SHA256SUMS.txt`。不要把更新签名密钥复制到测试电脑。

- [ ] 安装完成后正常启动；本地服务能打开登录页。
- [ ] Haze 登录完成后回到桌面应用，能进入首页。
- [ ] 原有会话和配置可见；能创建一次测试对话并得到回复。
- [ ] 自动化应用可以打开，并完成一次无副作用的测试运行。
- [ ] 最新版不显示头像上方的更新按钮；“帮助 → 检查更新”仍能打开更新窗口并检查版本。
- [ ] 开发版本不会尝试下载安装；正式安装版可以检查版本。
- [ ] 从旧版共享会话密钥迁移，允许首次重新登录；不应丢失会话和模型配置。

草稿 Release 没有公开更新地址，不能用“草稿未发布时检查不到版本”判断更新器损坏。
第一版包含更新器的安装包需要手动安装一次。

## 第二轮：0.8.8 → 更高版本

需要两个真实安装包。保持当前 0.8.8 作为基线；只有准备下一次测试发布时才创建例如
0.8.9 的新版本和对应说明。不要为了准备验收而提前修改当前版本。
应用内真实下载需要更高版本的更新文件和清单对测试客户端可访问；私有草稿不能直接作为
当前公开更新地址的响应。如果尚不适合向全部用户发布，先采用独立测试发布通道。

在 0.8.8 中准备一条测试会话、模型配置和一个测试网站账号。结束任务并从托盘退出 Eureka 后：

```powershell
npm run desktop:verify -- before
```

报告保存在被 Git 忽略的 `desktop/verification/`。脚本只读取选定数据的文件指纹和大小，
不导出会话正文、密钥、API Key 或 Cookie，不启动程序、不登录、不访问网络。
这不是备份工具，也不是完整的升级成功证明。发现已有基线时会拒绝覆盖。

- [ ] 检查到更高版本后，头像上方显示更新按钮；“帮助 → 检查更新”中版本号和更新说明正确。
- [ ] 第一次点击头像上方的更新按钮，直接开始后台下载；悬停显示进度，下载时再次点击可打开进度窗口。
- [ ] 关闭更新窗口，下载继续；重开窗口状态正确。
- [ ] 下载完成后不会自动安装，按钮提示“关闭 Eureka 并更新到”目标版本；再次点击才退出并安装，也可从更新窗口点击“关闭 Eureka 并更新”。
- [ ] 有聊天或自动化任务运行时，安装被拒绝，任务继续；结束任务后能重试。
- [ ] 安装过程中应用真正退出，Node/自动化子进程释放，没有文件占用提示。
- [ ] 安装后应用重新打开；网页、帮助菜单和安装程序显示同一新版本。
- [ ] 会话、模型设置、自动化登记及账号元数据保留。
- [ ] 已登录的网站账号仍可使用；本地会话密钥保留，正常升级不重复要求登录。

完成升级，先不进行额外的数据编辑。退出 Eureka 后：

```powershell
npm run desktop:verify -- after
```

检查 `desktop/verification/report.json`：文件缺失或原有本机会话密钥改变会判为需复核；
登录令牌刷新、窗口状态等文件变化只列入 changed，不能据此直接判断数据损坏。
浏览器 Cookie、启动、登录和应用内更新是否正常仍按上面的人工步骤确认。
报告含本地路径和文件指纹，请留在本机，不作为 Release 附件上传。

## 失败恢复与发布判定

- [ ] 断网或下载失败：显示错误，可重试，旧版仍能使用。
- [ ] 更新文件签名错误：拒绝安装，保留原安装。
- [ ] 安装前服务状态不可确认：拒绝安装，重试或重新打开后可恢复。
- [ ] 安装器启动失败：应用可恢复本地服务，数据保留。
- [ ] 验收未通过：保留草稿，记录失败步骤和复现条件，不对用户发布。

现有自动化测试覆盖了签名拒绝、任务准入、状态恢复和界面行为；真实 NSIS 安装、
Windows 文件占用、登录回调和跨版本数据保留需要使用生成的安装包完成。
