## v0.90 修正与复测

- 原因：v0.89 已按所选功能加载流程图，但启动工作进程时仍使用包的默认入口。选择“逐行去重”时实际执行的是两节点的统计脚本；日志的完成对应这个错误入口，并非四节点去重流程已经完成。
- 修正：工作进程、流程图及结果列使用同一功能快照，运行记录新增可选的 `entryScript`，保存实际启动的相对脚本路径。目录、创建预览和聊天都复用此运行器。历史记录保持原有真实事件，不补写成功；分支中没有走到的节点仍可显示“未执行”。
- 按钮：按 [shadcn Base UI Button Group](https://ui.shadcn.com/docs/components/base/button-group) 的组合方式补充公共 `ButtonGroup`、`ButtonGroupSeparator`、`ButtonGroupText` 与 `Separator`，复用现有 Button 和 DropdownMenu。运行按钮保留原主题配色，两侧等高、统一圆角；功能菜单加宽，名称与说明分层。

已安装上轮示例包的用户无需重新下载、导入或修改应用：

1. 重启开发服务（`npm run dev`）并刷新页面；本轮不需要重新编译桌面程序。
2. 打开“文本处理工具箱”，选择“逐行去重”，配置三行 `a`、`a`、`b` 后运行。新记录应完成全部 4 个节点，结果只有 `a`、`b` 两行；日志应包含 4 个节点的真实完成事件。
3. 切换“转为大写”，输入 `hello`，新记录应完成 3 个节点，输出 `HELLO`；“统计字数”仍完成 2 个节点。历史中原先错误入口产生的记录不作改写。
4. 检查主按钮和箭头等高，功能菜单说明不再挤成窄列；Tab 可分别聚焦主按钮与箭头，菜单选择只切换功能、不自动运行。创建预览应显示相同按钮与菜单。

## 交互

- 一个应用包含多个功能，右上角使用“运行功能名＋下拉箭头”的分体按钮。下拉只选择功能，不立即执行；主按钮启动当前功能。
- 配置弹窗、画布、结果列、日志及运行记录随功能切换。相同字段名在不同功能中也分别保存，不要求填写其他功能的必填参数。
- 运行中及启动结果未确认时不允许切换功能。停止只作用于本次运行，停止／失败后可以显式再次运行。
- 浏览器环境和现有网页操作授权仍归应用管理，同一环境的登录按既有多页面规则共享。功能可声明应用能力的子集，未声明写能力的功能不能执行网页变更。
- 创建预览复用运行页，可切换查看每个功能并填写配置；实际试运行仍由原对话的 AI 工具发起，不把用户手动操作当作校验通过。
- 聊天调用仍没有嵌入式运行界面。AI 先读取功能清单，再通过 `actionId` 选择需要的功能，读取该功能保存的配置并逐步执行；含糊时才澄清。
- 新生成的查询应用默认直接返回结构化明细。CSV／JSON 不是多功能包的必需节点；原本目标就是文件处理／生成文件的功能仍可产出文件。本轮不自动重写旧应用内已有的导出代码。

## 包结构

继续使用普通插件安装管理，不增加新的扩展类型。旧单流程包仍可使用原来的 `entry/ui/workflow`；旧多按钮包继续按 `ctx.action` 分支执行，共用旧配置和原流程图。

新包在 `plugin.json` 的 `extensions["com.eureka"].automation` 中增加可选 `actions`（最多 32 项）：

```json
{
  "entry": "scripts/create.mjs",
  "ui": "ui.json",
  "workflow": "workflow.json",
  "actions": [
    {
      "id": "create",
      "label": "创建活动",
      "description": "创建新的闪降活动",
      "entry": "scripts/create.mjs",
      "ui": "ui.json",
      "workflow": "workflow.json",
      "capabilities": ["browser.read", "browser.write"]
    },
    {
      "id": "add",
      "label": "添加商品",
      "entry": "scripts/add.mjs",
      "ui": "ui/add.json",
      "workflow": "workflows/add.json",
      "capabilities": ["files.read", "browser.read", "browser.write"]
    }
  ]
}
```

这是清单片段，不是完整插件。根 `capabilities` 包含全部功能需要的能力；每个功能的能力只能是其子集。根入口／界面／流程保留为默认首个功能；每个被引用的界面与流程使用原有 JSON 结构，并全部列入发布清单。

每个功能 UI 的 `buttons` 使用自己的 ID。宿主从功能声明统一生成选择菜单；各入口依旧默认导出 `async run(ctx)`，实际操作放在 `await ctx.step(...)` 中。不同功能可复用模块，字段和节点 ID 只需在所属功能内唯一。

文本配置可声明 `multiline:true`，使用现有 Textarea 保留换行；普通文本配置继续使用单行输入。

新增发布目录只允许 `ui/<名称>.json` 和 `workflows/<名称>.json`。配置、授权、样本和运行记录仍不能放入包内。

新功能包需要更新后的 Eureka 客户端；旧客户端尚不认识 `actions`。已有应用不会自动被拆分成多功能，需要用“AI修改”生成并验证新版本。

## 数据与校验

- 新多功能包的配置保存在 `app-data/<用户>/<应用>/action-config/<功能>.json`，文件授权保存在对应 `action-grants/<功能>.json`；浏览器设置和网页授权继续共用应用原位置。
- 旧包继续使用 `config.json` 和 `grants.json`。升级旧包为新多功能声明时需要为各功能重新确认配置与文件授权，不自动猜测旧字段应归哪个功能。
- 启动时冻结功能 ID、名称、流程和结果列。历史记录按功能过滤、按时间倒序；不会套用另一功能的画布。
- 创建任务的 `actionTrials` 分别记录功能的私有校验规则、试运行 ID 和结果。切换功能不抹掉已通过的其他功能。代码变化后全部功能的校验失效；仅更新某功能的私有检查规则时，只重新核对它的同一运行。
- 新多功能应用全部功能分别通过当前代码版本的实际试运行校验后才能保存，不会将一个功能通过当成全部通过。网页变更仍使用原有操作授权与结果核对，不为验收自动重复提交。
- 导出、另存、组织扩展安装继续只处理发布清单中的代码和声明；安装者使用自己的配置、文件和网页登录。

## 用户验收

1. 刷新自动化页面，标题菜单不再出现测试包下载入口，正式应用的导入与列表刷新继续保留。
2. 当前按钮效果保持不变；后续创建的多功能应用在预览和运行页使用相同控件。
3. 使用已有应用或通过首页创建多功能应用，分别检查各功能的独立配置、流程、结果和运行记录；只完成一个功能校验时，保存不能标为全部通过。
4. 原有单流程应用继续使用单个运行按钮；旧数据不迁移或删除。
