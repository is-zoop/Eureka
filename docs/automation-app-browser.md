# A04：通用网页能力与持续授权

状态：2026-10-31 已由用户确认测试成功。以下保留 A04 交付说明和原验收步骤；当前 A05 已接入、待用户编译和测试，见 [A05 首页创建闭环](./automation-app-authoring.md)。开发者未运行编译、类型检查、测试或网页验证。

## 这一步能做什么

独立应用现在可以用同一套 SDK 打开 Eureka 的原生侧边浏览器、等待人工登录、定位控件、读取任意声明的业务字段、提取表格和操作网页。没有固定商品字段、纯数字编号、三次查询或固定四节点要求。应用仍通过公共参数表单、画布、日志和结果组件展示。

查询使用 `browser.read`；业务变更还需要 `browser.write`、明确的操作声明、可靠的页面账号标记及页面状态校验。首次变更在应用页展示授权卡片，同范围后续运行持续使用。代码内容、网站、账号、浏览环境或声明的操作范围变化后，重新确认。

网页内容由原生 WebView2 直接显示，不传输视频画面，也不另起外部 Chrome。此阶段没有新增聊天循环；人工登录问题沿用现有澄清卡片。完整 AI 探索、代码生成、业务方法校验及首页保存卡片留在 A05。

## 先由你编译和启动

1. **彻底关闭当前 Eureka 桌面测试程序，包括托盘中的实例**，避免 eureka.exe 被占用导致“拒绝访问”。保留开发服务终端。
2. PowerShell 执行：

   ```powershell
   cd E:\Eureka\desktop
   .\node_modules\.bin\tauri.cmd build --debug --no-bundle --config src-tauri/tauri.dev.conf.json
   ```

3. 另一个终端启动或重启开发服务：

   ```powershell
   cd E:\Eureka
   npm run dev
   ```

4. 双击 `E:\Eureka\测试原生侧栏浏览器.cmd`，或沿用你之前成功的原生预览启动方式。它连接 `http://127.0.0.1:8080` 的开发服务。不要直接双击缺少开发环境参数的 exe，也不要执行 `next build`。

本轮变更新增了原生命令 `desktop_automation_app` 和固定 DOM 适配器。只刷新网页不会更新这部分代码；ACL 生成文件由你的原生构建更新，不手工伪造构建结果。

## 第一轮验收：先测这几项

原 A04 验收入口曾为“自动化 → 管理应用包 → A04 可运行示例：通用网页”，现已移除该管理页与示例下载界面。已有 ZIP 使用自动化侧栏“…” → 导入应用包，预览并安装；当前入口见[目录精简](./automation-directory-simplification.md)。下文保留历史示例的验收步骤。

### 不同页面读取不同字段

安装“多页面字段查询”，配置保持 `page=products`、查询标识 `DEMO-001,DEMO-002`，点击“查询并提取”。

- 右侧打开本机模拟商品页。默认模拟账号 A 已登录；四个节点依次出现真实执行事件。
- 应提取 `DEMO-001` 的价格 659、库存 **0**、销量 1446；`DEMO-002` 价格 839、库存 12、销量 839。完整字段可下载“查询结果.json”；不适用的输出列显示“—”。
- 将 `page` 改为 `marketing` 后再次运行。应打开模拟营销页，输出营销编号 `10030087793610`／`10030087793611`、费率 10／**0**、日期、标签列表、附加对象；可空数字为 **null**，不填成 0。
- 两个页面使用相同运行器和 UI。所有数据都是模拟，与真实店铺无关；此测试不代表淘宝业务已验证。

### 人工登录等待

在运行结束后的右侧页面，把“切换模拟账号”设为“退出模拟登录”，再启动应用。

- 应停在连接节点，出现“登录或人工验证”澄清卡片。
- 在右侧选择“演示账号 A”或 B，再在卡片选择“已完成，继续”并提交。
- 宿主重新读取账号后继续。仍未登录时应失败，不假装读取成功。实际网站若跳到独立登录域名，应由你完成登录并返回声明的业务入口再继续。

### 首次变更授权及重复使用

安装“网页选项操作 1.0.0”，保持“启用演示选项=是”，点击“设置并校验”。

- 应打开模拟设置页，出现“确认网页操作范围”卡片，显示运行版本、网站、当前账号、浏览环境、操作说明和本次输入。
- 点“允许选定范围并继续”后执行勾选，读取状态，结果 `enabled=true`；画布按三个节点报告实际执行。
- 把参数改为“否”后再次运行，同账号、同浏览环境、同代码、同操作范围应直接执行，不再次询问，结果 `enabled=false`。
- 校验指声明的页面状态满足预期，不把勾选状态或派发回执写成后端业务成功。

### 换账号、换版本、撤销

- 运行结束后，在网页选择模拟账号 B；再次运行，应重新显示范围授权，不能复用 A 的授权。
- 在授权卡片等待时，把网页账号换成另一个，再点允许。应提示账号变化，不保存旧账号授权，不派发变更；停止该轮后重新运行。
- 下载导入“网页选项操作 1.1.0”，再次运行。即使选择相同账号也应重新授权；旧运行固定原代码版本。
- 展开“网页环境与持续授权”，点击某条授权的“撤销”。相关网页运行停止，该授权记录不再生效；之后新运行重新确认。
- 可改为“临时浏览器”，保存环境后再运行；临时环境关闭即清理，不承诺跨环境复用登录或授权。运行中不能修改浏览环境。

## 异常和兼容验收

| 你的操作 | 预期结果 |
| --- | --- |
| 首次授权卡片点击“拒绝并停止” | 停止该轮，不勾选、不保存授权 |
| 控制期间点击浏览器“暂停”、隐藏／关闭侧栏、切换应用或离开自动化页 | 停止网页运行、释放手动操作；后续不自动派发旧命令 |
| 等待登录／授权时刷新界面，或重启服务 | 旧运行停止或标记中断；不恢复控制令牌、不接管旧队列、不自动续跑 |
| 运行结束后在地址栏进入声明范围以外的页面 | 该页不允许应用读取或操作；新运行重新连接入口 |
| 两个网页应用同时申请侧栏 | 后申请的应用得到占用提示；不共享旧账号绑定或控制令牌 |
| 旧内置商品查询下线 | 旧入口消失，已保存独立应用仍能运行；见 [下线说明](./automation-legacy-retirement.md) |
| A03 文件清单应用运行一次，普通会话／首页澄清一次 | 原功能继续可用；首页仍明确 A05 未接入 |
| 从已运行应用导出 ZIP 并检查内容 | 只有发布清单中的代码与声明，不含 browser-grants.json、browser-settings.json、配置、日志、账号、结果或产物 |

**未知结果测试（只操作本机示例）**：先正常运行选项应用一次，使页面保留在右侧。在网页手动勾选“模拟变更后页面校验不可用”，然后运行相反的勾选参数（当前真则填否，当前假则填是）。模拟页面在实际变更后移除校验定位。该轮应中断并提示结果未确认，不自动再次点击，也不能显示成功。刷新模拟网页恢复定位，再取消“模拟变更后页面校验不可用”；人工核对页面状态后再决定是否新建运行。此功能专为验收，不连接真实业务。

浏览器断开或未知结果时，页面动作可能已经发生。停止不表示撤销已发生的变更，系统不会自动回滚或重复提交。

## 应用开发约定

在 `plugin.json` 的 `extensions.com.eureka.automation` 中增加声明；网站、字段和操作 ID 由每个应用定义。下面只示意通用结构，不包含真实网站凭证或用户样本：

```json
{
  "capabilities": ["browser.read", "browser.write"],
  "browser": {
    "schemaVersion": 1,
    "sites": [{
      "id": "settings",
      "label": "业务后台设置",
      "startUrl": "https://example.com/settings",
      "paths": ["/settings"],
      "account": {"locator": {"testId": "current-account"}, "type": "text", "optional": true},
      "operations": [{
        "id": "enable",
        "label": "设置通知选项",
        "description": "修改当前账号的通知开关；不修改其他配置",
        "effect": "mutation",
        "kind": "check",
        "locator": {"label": "接收通知"},
        "verify": {"field": {"locator": {"label": "接收通知"}, "source": "checked", "type": "boolean"}, "mode": "equals", "input": true}
      }]
    }]
  }
}
```

| SDK | 作用 |
| --- | --- |
| `await ctx.browser.connect(siteId)` | 打开当前应用的原生侧栏，核对网站及账号；需要人工登录时发澄清卡片 |
| `await ctx.browser.locate(locator)` | 返回可见目标的角色、标签和禁用状态；不暴露 DOM 对象或旧引用 |
| `await ctx.browser.read(field)` | 读取一个明确定位的字段；缺失、类型错误、隐藏或凭证控件不伪造数值 |
| `await ctx.browser.extract({rows,fields,limit})` | 按行提取每个自定义字段；超过显式行数限制则报错，不默默截断 |
| `await ctx.browser.operation(operationId,{key?,value?})` | 执行包中声明的点击、填写、下拉选择、勾选或回车；变更核对持续授权及前后状态 |
| `await ctx.browser.navigate(url)` | 只导航到当前声明的网站路径范围内，不跟随任意外部链接 |
| `await ctx.browser.waitFor(field,expected,timeout=10000)` | 最多等待 30 秒，重复读取页面状态；不重发查询或变更 |
| `await ctx.browser.release()` | 放开人工操作；后续仍需重新核对账号和页面 |

定位支持 CSS、role＋name、label、精确 text、testId，及 `within`／`nth`。操作必须唯一定位，不靠旧 DOM 编号；可声明 `row:{locator,key:field}`，用 `key` 明确匹配某条业务记录，再在行内操作。填写值与记录键只是数据，不拼成任意脚本或选择器。

字段读取支持可见文本、表单值、勾选状态及少量明确属性；文本、数字、布尔、日期文本、百分数、对象和列表各自声明。长编号保留为文本，零、空字符串、null 和缺失分别处理。百分数字段 `10%` 返回 10；日期保留网页文本，不猜测时区。JSON 对象／列表解析保留内部字符串。读取链接只保留域名和路径，不带查询凭证。

## 授权、数据和生命周期

- 同一原生浏览器只供一个网页应用运行使用；文件应用仍由自己的进程运行。当前应用页承担浏览器命令传递，不重新探索任务。
- 运行、节点与日志使用 A03 的同一事件流，登录／授权等待附着实际节点；旧记录没有步骤时不补写成功。
- 操作前检查当前 Haze 用户及登录代次、原运行代码、网站路径、浏览环境代次和页面账号。网页内容变化、控件被替换或遮挡时不盲点。
- 每次原生派发前消费仅供本次命令的一次性本机授权凭证；它绑定完整声明和输入，最终核对当前运行及授权。凭证不提供给应用脚本、网页或导出包。暂停先使旧控制序号失效，再释放原生输入。
- 持续授权按用户数据目录存储，绑定完整代码摘要、网站、环境代次、页面账号摘要和操作范围摘要。浏览器 Cookie、密码和模型凭证继续由宿主管理，不由应用复制。
- 用户浏览环境选择存于 `app-data/<用户>/<应用ID>/browser-settings.json`；授权存于同目录 `browser-grants.json`。运行记录、实际账号标记和状态证据同样只写用户数据，不写插件目录。
- 安装、扫描、详情、导出只读发布声明，不执行网页操作或安装脚本。已声明能力不等于已授权。

### 实际边界

本轮通用适配器操作顶层可见 DOM，不声称已经支持所有网站：跨域 iframe、闭合 Shadow DOM、纯画布、必须可信原生输入的网站和后端专用接口仍需后续适配。没有任意 JS/CDP 执行入口，没有 Cookie／签名导出接口，也不处理验证码。账号标记必须由应用使用能代表实际登录账号的可见字段；页面标题或登录框里待填写的用户名不足以证明登录身份。

`query`／`mutation` 是应用包对动作真实语义的声明。宿主会拦截凭证控件和明显的危险查询控件，但无法只靠按钮文字证明网站事件不会产生后端变更。应用作者必须如实声明副作用，并选择能证明所需业务状态的校验字段；不能把任意动作伪装为只读。代码包和网页适配器仍需审阅，独立进程不是完整安全沙箱。
