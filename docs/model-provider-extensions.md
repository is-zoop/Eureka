# 扩展模型服务商

2026-11-09：参考 pi-web 的扩展服务商加载方式，Eureka 的服务商列表和认证入口现在使用与聊天相同的 SDK 扩展注册机制。

## 本次补齐

当前 Pi 全局安装了 `npm:pi-provider-workbuddy`，该扩展注册两个地区：

| 服务商 ID | 显示名称 | 认证 |
| --- | --- | --- |
| `workbuddy` | WorkBuddy (CN) | OAuth |
| `workbuddy-global` | WorkBuddy AI (Global) | OAuth |

它们来自已安装扩展，未硬编码进 SDK 内置服务商目录。其他已启用的全局扩展服务商也通过同一入口发现，分类继续依据实际 API Key／OAuth 能力。

在模型设置中点击“添加服务商”，搜索 WorkBuddy，选择对应地区并完成登录。两个地区分别保存 Pi 凭证，退出其中一个不会删除另一个地区的凭证。模型、上下文窗口、思考级别和额度倍率沿用扩展注册的信息，未复制固定模型清单。

## 实现

- `lib/provider-model-runtime.ts` 创建不包含 AgentSession 的扩展模型运行时，加载安装目录的全局扩展，不授权项目本地扩展。
- 状态读取共用运行时，每次串行离线刷新凭证和 models.json；OAuth 登录使用独立实例。
- 模型缓存失效也会使扩展运行时重建；插件安装、更新、启停、删除和会话 reload 能刷新列表。
- API Key 读写及 OAuth 退出保留原来的凭证类型检查与文件锁，状态接口不返回密钥。
- 自动化 AI 判断同样可以使用扩展服务商作为默认模型。聊天与模型选择器原有的扩展加载流程继续使用 SDK 服务。
- Kimi 请求兼容和旧 Azure 服务商兼容继续保留；未改动 MCP 与自动化文件权限。

## 验证与生效

真实 `/api/auth/providers` 已返回两个 WorkBuddy 服务商；当前安装的扩展目录分别提供国内 16 个、国际 3 个模型，实际数量会随账号和扩展更新变化。`/api/auth/all-providers` 正常返回，WorkBuddy 沿用其实际 OAuth 能力分类。

25 项相关回归通过，包括 SDK 服务商能力、模拟 OAuth 登录事件流、凭证刷新、API Key 保存／删除、地区退出隔离、模型分派、缓存失效与原有兼容行为。未向真实 WorkBuddy 发送聊天请求，模拟调用不消耗真实额度。

本次没有 Rust 改动。开发服务已热更新接口，重新打开模型设置即可查看；仍显示旧列表时重启开发服务并刷新页面，无需重新编译桌面程序。全新安装只有在启用相应 Pi 扩展包后才会显示扩展服务商。
