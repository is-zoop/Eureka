# 通用自动化应用改造

创建入口位于首页现有对话：输入框添加菜单中的“自动化”与 `/automation` 使用同一模式。创建后在原对话命名保存，从自动化目录使用应用。取消独立创建页；目录的创建按钮跳到首页新对话并选中模式，不自动提交需求。

目标应用包包含 plugin.json、package.json、ui.json、workflow.json、scripts/、可选 ai/ 和说明文件，业务逻辑归应用所有。使用 JavaScript ESM 和宿主 SDK，支持纯脚本与脚本加 AI；Pi loop、会话、澄清和登录浏览器继续复用。公共 UI 根据应用声明渲染，节点数量、分支、循环由流程定义及实际事件决定，不固定商品字段、四节点或三编号。

本轮不做通用桌面控制；本地文件由脚本处理。网页变更首次授权后持续使用，授权绑定用户、代码版本、网站、账号环境和操作范围，变化或撤销后重新确认。本地导入导出先完成，Haze 分发另行联调。Python 适配后置。

代码包以不可变版本放在 Pi agent 目录下（通常为 `~/.pi/agent`，支持现有自定义目录）：


插件目录中的用户摘要仅作安装命名空间，目录内不写用户配置、登录或证据。浏览器登录及模型凭证继续由宿主保存，应用包里不放这些信息。重新安装同 ID 应用继续使用本机数据；更新保留配置及旧代码记录，只使用最新版本。卸载移除本用户登记及代码，默认保留数据；清理数据是独立的明确确认操作。

详情显示的能力为代码包声明，不等于已经授予文件访问或网页操作权限。安装、列表扫描、打开详情和导出都不 import 或执行入口脚本，不安装依赖。A02 没有运行进程；A03 接入运行器时必须同时接入运行版本固定和租约，防止更新／卸载影响正在运行的任务。本轮不将独立进程称作安全沙箱。

发布清单位于 `extensions.com.eureka.automation.files`，必须与导入包实际文件一致。只允许根声明及说明、`scripts/`、`ai/` 和 `assets/` 中支持的资源；配置、日志、证据、产物、授权及 `.env` 等路径不得发布。导出只重新读取这份发布清单，并核对安装时内容摘要，不递归压缩代码目录，更不读取 app-data。路径、大小、重复文件、链接、依赖及安装脚本在导入时检查。包大小上限 20 MiB，展开内容上限 16 MiB，最多 256 个发布文件；这些是资源限制，不限定业务字段和节点数量。

清单隔离不等于扫描任意源码中嵌入的隐私；生成或手工编写包时仍不得将真实样本、密钥或用户配置写进代码／说明。未来 A05 的生成器只向工作区写可发布代码，探索证据单独保存。

7. 卸载后，应用从侧边栏消失，“管理应用包”里的“卸载后保留的数据”仍有记录。点击该条目的“清理数据”并确认，记录和测试数据才应删除。对已安装应用清理数据应保留代码与应用登记。
8. 切换 Haze 账号，不能看到前一个账号的独立应用登记或保留数据；导入同一个 ZIP 时使用新账号自己的空配置，不读取原用户数据。首页普通聊天和原 Skill／HTTP MCP 扩展仍按原方式使用；旧内置工具已下线。

## A01 实际能力
