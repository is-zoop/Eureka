# 会话、自动化运行与网页连接的生命周期

2026-11-02，v0.73。此轮仅修改 TypeScript／React 和文档，无需原生编译。开发者未运行编译、测试、模型或真实网页操作。

## 统一规则

聊天由后端 Pi loop 执行，页面是消息的订阅者。刷新、切页、切换会话、隐藏面板和组件卸载只改变订阅及网页展示，不等于取消后端任务。自然完成、等待用户、等待网页、用户取消、执行失败和进程中断分别记录，不统一显示“用户停止”。

自动化代码需要网页时，网页不可用则进入 `waiting-browser`，保留任务、运行 ID、参数、步骤和证据；恢复连接后继续同一运行。仅恢复连接和已派发网页操作的重新执行是两回事。

## 本次排查结果与修改

| 来源 | 原行为 | 当前行为 |
| --- | --- | --- |
| 首页与自动化目录导航 | 广播暂停，断开网页时进一步取消创建 | 只切换显示，浏览目录不取消首页任务 |
| 刷新与页面卸载 | `pagehide` 发送创建暂停，组件清理也会暂停 | 移除自动暂停；只发送网页 `detach`，不发送停止 |
| 切换首页会话 | 暂停前一个创建任务 | 前一任务保留；需要网页的步骤等待其界面返回 |
| 浏览器心跳丢失 | 几秒后中断运行 | 连接租约过期后允许同用户、同登录代次、同任务和运行的页面重新连接；等待本身不取消任务 |
| 打开模态弹窗、隐藏侧栏或页面暂不可见 | 遮罩触发全局暂停，隐藏导致离开运行 | 发布网页可用状态；不可用时不派发新动作，关闭遮罩后可继续原运行 |
| 原生视图组件卸载 | 关闭网页视图，可能导致重新导航 | 释放控制并隐藏视图；刷新后恢复同一个仍存在的原生视图，不主动导航回入口 |
| 刷新后的控制序号 | 新文档从零开始，旧原生视图拒绝控制 | 新文档使用更大的序号，迟到的旧控制意图不能覆盖新控制 |
| 临时网络或服务读取失败 | 直接关闭原生视图 | 临时读取失败重试；明确身份失效仍撤销控制 |
| 候选试运行失败 | 含写入能力时停止整个创建任务 | 保留会话和草稿，返回该次运行的真实失败；含变更的再次执行仍需用户明确继续 |
| 正常结束网页探索 | 也记成 cancelled | 正常释放记为 completed，已失败／中断状态不覆盖 |
| 停止／拒绝授权 | 全局事件可能影响其他任务 | 显式停止携带任务／运行归属；拒绝、撤销通过所属应用接口执行，不广播停止其他会话 |
| 运行中创建分支／切换历史分支／手动压缩／重新加载扩展 | 可能销毁或改变当前执行环境，或依赖 SDK 的不一致处理 | 后端明确拒绝这次界面操作并保留原任务，提示等待完成 |

普通会话的 SSE 断开只清理订阅；现有十分钟回收仅针对非运行中的闲置会话，不因浏览页面而终止正在运行的 Pi loop。澄清卡片使当前轮等待回答，是正常等待，不是取消。

删除会话会清理其运行与浏览器；退出桌面程序或停止开发服务会结束对应进程。这些明确结束／删除行为仍按原方式处理，不能保留一个继续写入已删除会话的后台执行。

## 重连与结果未知

- 尚未派发的命令可在恢复后重新领取；旧票据和旧领取凭证同时失效。
- `probe/observe/locate/read/extract` 是固定的无网页变更读取，丢失回执时允许重新观察。它们的旧回执不能覆盖新的领取结果。
- 已派发的点击、填写、选择、回车、导航等动作不自动重做。旧执行若稍后返回，仍须通过原领取凭证核对；结果持续未知时报告真实异常。变更结果未知时该次运行标记中断，要求人工核对，会话和草稿保留。
- 派发票据同时绑定不可变的连接 ID 和领取凭证，在异步权限检查前后都核对，防止旧页面的票据借用重连后的命令状态。
- 模态出现与派发之间存在的竞态，只有确认未派发的动作或固定只读观察可以延后；真正已派发的变更不按“稍后再做”重放。

以下情况不能宣称任务始终在运行：开发服务／执行进程退出、账号或授权失效、脚本异常、执行占用丢失、原生视图真实丢失或原生租约过期、已派发变更结果不明。这些属于失败或中断，不是用户取消，也不自动重跑。原生层原有身份与视图租约保留；长时间未能恢复前端时，若原视图已消失，不新开入口页面冒充原页面继续执行。

脚本保留三十分钟实际执行时间限制；等待网页或用户的时间不计入。脚本结束、执行资源上限或进程崩溃等仍需准确报告，不能用“只有用户停止”掩盖真实失败。

## 用户验收

本轮包含服务端生命周期改动。先保存进度、结束当前需保护的执行，再重启根目录 `npm run dev`，刷新 Eureka；之后启动验收任务。重启开发服务与只刷新页面不同，前者会结束当前进程，不能据此判断刷新恢复失败。

1. 普通聊天输出期间刷新，再切到自动化页、返回首页及切换会话。原会话不收到取消，返回后恢复原输出和状态，不重新发送用户需求。
2. 在首页自动化网页任务的读取阶段刷新，确认原生页面及登录仍存在。运行 ID 不变，显示等待重连后继续；不新建任务、不重复查询按钮动作。
3. 打开配置弹窗、隐藏网页、切换会话，再关闭弹窗／恢复原会话与网页。需要网页的步骤等待，文件与普通会话任务不被全局取消。
4. 暂时断开界面连接后恢复，检查日志与步骤没有虚构成功，旧结果不覆盖新的读取，已派发变更没有再次提交。
5. 点击所属会话停止、退出创建模式或拒绝授权，确认只取消所属任务；切页或刷新后不自动重启已被用户取消的运行。
6. 若原生视图已关闭、账号变化或开发服务已重启，应看到准确的中断原因与保留的草稿，不能自动重做未知网页操作。
