# Haze 原生 MCP 接入

更新日期：2026-11-06。Pi SDK `1.5.0`。

## 当前结果

Eureka 的 AgentSession 已改为使用 SDK 的 `createMcpExtension()`，配合 SDK 原生 HTTP/stdio 传输、工具搜索及 Codemode。Haze 服务通过公开 `pi.registerMcpServer()` 登记，生产扩展列表不再加载旧 MCP 代理。

按本轮要求，不迁移旧 MCP 配置文件，也不转换历史工具名称和调用格式。旧文件未被删除。Haze 市场登记仍用于识别已经安装的服务和插件；随后安装的 Haze 插件也走原生接入流程。

**代码、本地端到端验证，以及真实 Haze 认证、工具发现和市场只读调用均已完成。** 用户重新登录后，使用当前运行时登录验证了两个真实服务；没有迁移旧配置、创建 Atlas 业务会话或修改选数范围。Atlas 完整业务查询及桌面安装仍需分别验收。

## 认证与请求流程

1. 会话启动时，绑定当前 Haze 的发行方、账号、运行时登录 ID 和身份提供方；读取安装登记、项目信任和已批准的插件服务地址。
2. 原生 MCP 每次 HTTP 请求前，重新核对登录与服务登记。需要认证的服务会在宿主内读取共享 OAuth 状态；访问令牌过期时，在原有跨进程文件锁内刷新并保存旋转后的令牌。
3. 调用 Haze `/api/auth/me/mcp-credential` 取得当前个人 MCP key，仅放入这一次出站请求的 Authorization。重置个人 key 后，下一次请求获取新 key；不缓存到配置、环境变量、会话转录或状态接口。
4. 对工具和资源请求，另外核对当前任务是否选择了插件、工具是否被禁用、是否处于只读计划阶段、项目是否仍受信任、服务地址授权是否仍有效。
5. 获取凭证后、发送前以及读取响应期间再次检查。换账号、注销、取消或任务变化后，未发送的请求和迟到的响应不会继续进入模型。MCP 地址重定向不会携带凭证跳转。

OAuth 刷新已收到旋转令牌时，即使原工具调用被取消，也会先在锁内完成持久化；随后取消的 MCP 调用不会被发出。这与原有浏览器及独立认证进程共享相同的运行时状态文件。

无认证的组织插件服务不会获得 Haze MCP key，但仍受账号、服务登记、插件选择与地址授权边界约束。

## 当前功能

| 功能 | 接入结果 |
| --- | --- |
| Haze OAuth 刷新与旋转保存 | 已接入，沿用现有加密状态与文件锁 |
| 个人 MCP key 获取与重置 | 每次请求重新获取；本地重置测试通过 |
| 工具调用与资源读取 | 原生 Agent 工具循环通过 |
| 插件选择、工具禁用、授权撤销 | 在实际 HTTP 出站边界检查，直接调用、资源读取和 Codemode 均受约束 |
| 换账号、注销与取消 | 凭证等待和响应流均检查；迟到的旧账号数据丢弃 |
| 连接状态 | 原生传输事件转换为网页现有状态；输出安全计数，不输出地址、请求头或 key |
| 右侧浏览器 | 支持原生结构化结果；直接调用和 Codemode 都清除临时启动链接，并保持一次结果只打开一次 |
| 分叉与直接销毁 | 主机显式关闭原生传输，并按分叉前的会话 ID 清理绑定与状态，避免依赖 SDK 未触发的关闭事件 |
| 新手动 MCP 配置 | 设置页使用原生路径与字段，保存后重载会话 |
| 旧配置、旧工具格式 | 本轮不兼容、不迁移 |

Haze 服务当前采用 `direct` 曝光：连接完成后可直接调用原生工具。新原生配置也可以使用 `deferred` 或 `codemode`，相应 SDK 工具已加载；设置页新建服务默认采用 `direct`。

## 新配置约定

- 用户配置：`~/.pi/agent/mcp.json`；设置了 `PI_CODING_AGENT_DIR` 时使用该目录。
- 项目配置：`<cwd>/.pi/mcp.json`，仅在项目受信任时加载。
- 原生字段：`command/args/cwd/env` 或 `url/headers`，以及 `enabled`、`exposure`、`timeout`（秒）。设置页已使用请求超时，不再保存旧适配器的生命周期与空闲断开字段。
- 设置页的 Bearer Token 环境变量转换为 `headers.Authorization: "Bearer ${VARIABLE}"`，不保存实际值。
- 宿主自定义传输支持明确的环境变量引用；请求头和环境变量中的 `!command` 形式暂不执行。stdio 的可执行文件与参数正常支持。
- 不读取旧的 `.mcp.json` 和 `~/.config/mcp/mcp.json`；原文件保留，按需在新设置页重新添加。
- 原生客户端使用 Streamable HTTP，不提供旧 HTTP SSE 传输兼容。

Haze 市场接入不要求填写 Bearer Token 或手动复制个人 key；在 Eureka 登录 Haze，再安装或选择相应插件即可。

## 验证与待验收

`tests/shared/haze-native-mcp.integration.test.mjs` 的 9 项端到端测试使用真实 SDK、原生 HTTP MCP 客户端、真实 Agent 回合和本地模拟 Haze/MCP 服务，验证：

1. OAuth 过期刷新、个人 key 重置、工具调用与资源读取。
2. 取消选择插件、禁用工具和撤销地址授权后不发出工具或资源请求。
3. 获取凭证期间切换账号，不把请求发给 MCP 服务。
4. 注销后丢弃迟到的 SSE 工具结果。
5. 原生浏览器结果清理与右侧交接，覆盖直接调用和 Codemode。
6. 取消凭证等待与拒绝地址重定向。
7. Codemode 调用遵守同一认证与插件选择规则。
8. 设置页生成的原生配置能被 SDK 读取、调用、编辑和禁用，文件只含环境变量引用。
9. 会话 ID 被分叉改写后，直接销毁宿主仍关闭旧原生传输、清理原会话绑定与状态，重复销毁保持安全。

全量回归、类型检查与 lint 结果记录在 [SDK 升级总清单](sdk-1.5-upgrade-checklist.md)。桌面安装包验收仍单独跟踪。

### 真实 Haze 验证（2026-11-06）

用户在 Eureka 完成登录后，采用当前项目的 `installHazeManagedMcpRuntime()` 与 `installNativeMcpRuntime()` 创建独立的真实 SDK AgentSession；使用内存会话及本地可控模型响应提交指定工具调用，避免产生付费模型请求或新增用户聊天记录。Haze 认证及 MCP 服务全部使用真实网络，运行时中没有旧代理参与。

| 验证 | 结果 |
| --- | --- |
| 获取个人 MCP 凭证 | 接口 HTTP 200；key 仅进入请求头，未输出或保存到测试配置 |
| 市场 MCP 初始化与工具发现 | 连接成功，4 个工具 |
| Atlas 插件初始化与工具发现 | 连接成功，10 个工具 |
| SDK 扩展错误 | 0 |
| 市场只读调用 | `list_mcps`，参数 `page=1, limit=1`；通过真实 Agent 工具循环成功返回 `items/page/limit/total`，工具错误标记为 false |
| Atlas 会话边界 | `get_query_session` 使用明确不存在的测试 ID，返回预期的业务 `NOT_FOUND`；不属于业务查询成功验收，也没有创建或扩大业务会话 |
| 独立会话再次连接 | 两个服务再次连接成功，工具数量一致 |

首次探测出现过两个连接失败状态；加入脱敏 HTTP 诊断后重试、市场调用和独立重连均成功，未修改生产运行时代码。首次失败原因未能确定，后续未复现，保留此记录。

此轮没有强制使真实令牌过期、重置真实个人 key、注销账号或切换账号；这些破坏当前登录状态的情形仅在本地夹具中验证。没有发起 Atlas 指标查询、打开真实选数页面或验证安装包。真实 Atlas 业务查询仍需使用用户当前对话的有效 `session_id` 和选数版本。

脱敏本地诊断记录位于被 Git 忽略的 `.tmp/sdk-upgrade/haze-live-*.log`，永久记录仅保留上述结论与边界，不附加令牌、启动链接或业务数据。

旧 `pi-mcp-adapter` 依赖暂时保留，供既有参数兼容测试及现有资源准备脚本使用；它已经退出 AgentSession 的生产扩展列表。依赖清理与安装包验证可以后续完成，不会同时向 Haze 注册两套生产 MCP。

开发热重载可能保留已有 AgentSession；验证切换时使用重启后的 Eureka 和新会话，避免把旧运行时当作原生接入结果。
