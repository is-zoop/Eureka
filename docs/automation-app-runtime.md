# A03：本地脚本应用、公共运行界面与真实画布

状态：2026-10-31 已由用户确认测试完成。A04 通用网页能力已接入、待用户编译和测试，见 [A04 网页能力与验收](./automation-app-browser.md)；A05 首页 AI 生成完整应用尚未开始。以下保留 A03 交付时的说明与测试步骤。

当前界面及最新版本策略见 [画布优先运行页](./automation-run-workspace.md)；以下是 A03 的历史交付范围。

## 本阶段交付

| 项目 | 实际行为 |
| --- | --- |
| 独立运行 | 用户点击运行后才在本机 Node 环境启动脚本进程；安装和查看详情不执行脚本 |
| 版本固定 | 启动时核对版本摘要，将发布清单复制为本轮代码快照；运行记录保存当时的流程和结果列 |
| 用户数据 | 配置、授权、运行记录、输入输出及产物都位于当前用户的 app-data，插件目录不写运行数据 |
| 文件能力 | 只向 SDK 授予用户选择的文件／目录，以及应用自己的 workspace；不继承聊天文件允许列表 |
| 公共 UI | 按 ui.json 渲染参数、保存按钮、运行按钮、结果表格和下载；不为示例新增业务 React 页面 |
| 动态画布 | 节点数量来自 workflow.json，支持重复执行、分支、循环及等待用户；自动聚焦执行节点，可以暂停跟随查看历史 |
| 统一事件 | 画布、日志和步骤详情读取同一带运行 ID、节点 ID、执行序号、状态及输入输出引用的持久事件序列 |
| 停止 | 先通知脚本取消，再结束无响应脚本；脚本退出及在途 SDK 操作收尾后才释放执行占用 |
| 生命周期 | 同应用同时只运行一次；运行中不能卸载或清理数据；更新和切换当前版本不影响已启动版本 |
| 中断恢复 | 服务重启读取已存记录，标记中断，不重新 import 入口或继续原任务；刷新页面只观察 |

当前仅执行本地文件脚本。网页及 AI SDK 调用分别明确提示待 A04、A05 接入，不伪造网页或 AI 结果。运行页面不会调用另一套对话循环。脚本的等待用户复用 `UserInputCard` 和现有回答验证格式；首页创建继续复用 Pi loop。

停用阻止后续新运行，不代替“停止运行”；已经启动的版本由用户明确停止或等待结束。

## 开始测试

以下是 A03 当时的历史验收步骤。“管理应用包”页与示例下载入口现已移除；已有 ZIP 从自动化侧栏“…”导入，残留数据从设置管理，详见[当前入口](./automation-directory-simplification.md)。

本轮没有修改 Rust、Tauri、原生选择器或桌面配置。停止根目录原开发服务，执行 `npm run dev`，刷新 Eureka，不需要重新编译桌面程序，也不要执行 `next build`。开发者没有执行编译、类型检查、测试或界面验证。

### 安装新的可运行示例

1. 打开“自动化 → 管理应用包”，找到 **“A03 可运行示例：文件清单”**。
2. 下载 `文件清单 1.1.0`（文件名 `file-list-sdk-example-1.1.0.zip`）。下载到当前 Windows 下载文件夹；下载不等于安装。
3. 点击右上“导入应用包”，选择 ZIP，预览后“安装并设为当前版本”。侧边栏应出现 **“文件清单”**。
4. 打开应用，找到“配置与运行”。A02 的“应用包管理示例”保持原代码，只用于装卸测试，不会自动变成可运行的文件处理程序。

### 正常运行与循环

1. 在资源管理器准备一个测试文件夹，放入几个普通文本文件，至少包含一个空文件；不要选择宿主的 `.pi/agent`、插件目录或其上级目录。
2. 点击“待整理文件夹 → 选择文件夹”，由原生选择器选择测试目录。默认只读；当前示例不修改源文件。
3. “每项等待毫秒”填 `100`；后缀留空，“包括子文件夹名称”选“否”，“导出前询问”选“否”。点击“保存本机配置”，刷新确认保留。
4. 点击“生成文件清单”。应依次产生实际节点事件；“逐项整理”重复执行，卡片显示真实执行次数。结果中的空文件大小应为 `0`。
5. 点击某个节点查看输入、输出，在执行记录选择框中选择不同执行序号，核对不同文件的记录没有串用。手动查看时停止自动跟随，点击“恢复跟随执行”可继续。
6. 下载 `文件清单.csv`，与测试目录核对文件名、大小和修改时间。也可以下载完整 JSON 结果，保留原始类型。
7. 再次点击运行，形成新运行 ID；历史下拉框能查看旧结果和旧事件。刷新或切换页面返回不会额外新建运行。

画布连线是包内流程定义，使用中性虚线展示；只有节点的实际状态和事件记录代表执行。未走到的分支保留“未执行”，不补写成功。

### 分支和等待回答

1. 在增强版将后缀填 `.txt`，启用“导出前询问”，再次运行。
2. 筛选节点输出应只保留匹配名称；等待节点和顶部状态显示等待回答，出现现有澄清卡片。
3. 选择“生成 CSV”后继续真实导出；选择“只看结果”后返回已经整理的结果，不创建本轮 CSV，导出及其后节点保持未执行。
4. 等待时刷新同一页面，已有运行和问题应可继续回答；同一问题的重复提交不会再次放行脚本。
5. 运行中停止，问题结束后不接受迟到答案，不自动继续。

### 停止、异常和版本

1. 将每项等待设为 `1000`，使用多个文件运行，执行中点击“停止运行”。应先显示正在停止，再显示已停止；未完成节点不显示成功，重复点击不会创建新运行。
2. 运行中尝试卸载或清理本机数据，应提示先结束运行。停止收尾后才允许操作。
3. 另下载并导入同一“文件清单”的 `1.0.0`，可看到 3 节点；`1.1.0` 为 6 节点。运行中切换当前版本或导入更新，已启动记录仍显示自己的版本、流程、结果列和代码摘要。
4. 文件授权绑定代码内容，切换版本后应明确要求重新选择路径；参数配置保留，旧版本的授权不自动扩大到新代码。
5. 运行中停止开发服务，再重新 `npm run dev` 并刷新。原运行应成为已中断，不自动重跑；旧执行占用可能需要约 15 秒清理后才能启动新运行。
6. 选择目录后把它移走，再运行，应报路径或授权失效，不能用旧页面数据伪装成功。修复路径后由用户明确新建运行。
7. 网络启动响应不确定时，界面只提供“重试同一次启动”，沿用原运行 ID；后台也再次核对是否已有该 ID，不重放已经启动或结束的运行。
8. 切换 Haze 身份或重新登录，旧运行会停止，不继续用旧登录代次接收操作。不同账号不能读取对方配置、文件引用、运行、输入输出或产物。

文件写入不是事务回滚：取消或失败前可能已有部分文件操作完成，不能报告已撤销，更不能自动重试。应由用户查看日志与实际文件后再决定是否新建运行。

### 数据与旧功能回归

- 再次导出安装包，只包含原发布代码，不包含配置、文件路径授权、运行快照、日志、结果或产物。
- 卸载保留数据，重装后读取本机配置和历史；显式清理数据后应用代码保留，下次操作重建归属标记和空数据目录。
- 普通会话、首页自动化创建和 Skill／HTTP MCP 企业插件继续保留；旧“已有查询工具”已下线，见 [下线说明](./automation-legacy-retirement.md)。

## 脚本约定

入口为 JavaScript ESM 默认导出函数，不需要安装第三方依赖：

```js
export default async function run(ctx) {
  const entries = await ctx.step("read", { source: ctx.params.source.label },
    () => ctx.files.list(ctx.params.source));
  await ctx.step("output", { count: entries.length }, async () => {
    await ctx.log(`读取到 ${entries.length} 项`);
    return ctx.artifacts.write("清单.json", JSON.stringify(entries), "application/json");
  });
  return entries;
}
```

节点 ID 必须存在于 workflow.json。业务代码决定分支、循环和调用顺序；未执行的节点不产生事件，不将流程定义当作已经运行。所有 SDK 异步操作必须 `await`，不允许返回时仍有未完成操作。入口需要至少报告一个实际节点。

| SDK | 行为 |
| --- | --- |
| `ctx.params` / `ctx.config` | 本轮已验证的参数快照，保留文本长编号、数字、零、布尔、日期、百分比、对象和列表 |
| `ctx.runId`, `ctx.action`, `ctx.signal` | 本轮 ID、用户点击的按钮 ID 和取消信号；多个运行按钮可在同一入口中分派不同逻辑 |
| `ctx.step(id, input, async () => output)` | 主机分配执行序号，保存输入输出，发送真实开始／完成／失败事件；同节点可重复调用 |
| `ctx.log(text)` | 记录统一事件日志，附带当前节点与执行序号 |
| `ctx.sleep(ms)` | 可取消的等待，单次 0～60000 毫秒 |
| `ctx.files.workspace` | 应用自己的可用工作目录引用，实际路径仍由宿主管理 |
| `ctx.files.child(ref, "relative/path")` | 子路径引用，不能 `..` 越界、穿过链接或进入宿主目录 |
| `ctx.files.list(ref)` | 当前层目录项，返回名称、类型、大小、修改时间和文件引用；不跟随符号链接 |
| `readText(ref)` / `readJson(ref)` / `readBytes(ref)` | 读取已授权普通文件，二进制返回 Buffer |
| `writeText(ref, text, overwrite=false)` / `writeJson` / `writeBytes` | 写入已明确授权可写的位置，默认拒绝覆盖 |
| `mkdir(ref)` / `copy(from,to)` / `move(from,to)` | 受引用范围约束的目录创建、普通文件复制／移动；目标默认不得存在，失败不自动重试 |
| `ctx.artifacts.write(name, text, mediaType)` | 先实际写入本轮产物，再登记下载信息，不写插件目录 |
| `ctx.ask([{title,question,options,selection?}])` | 等待现有澄清卡片；返回验证后的答案列表，选项 ID 按声明顺序为 `"1"`、`"2"` 等，也保留自填和跳过状态 |

宿主不把用户输入的绝对路径直接当作脚本授权。UI 明确选择后，配置保存文件引用；宿主记录其用户、应用、配置项、读写范围和代码摘要。新版本重新授权。网页中的内容和澄清答案都不能自动扩大文件权限。

ui.json 配置项支持公开默认值 `default`，类型需要匹配，文件／目录字段不允许携带默认路径或用户授权。配置保存与运行使用修订号防止覆盖其他窗口的更新。

## 生命周期与执行边界

主服务通过独立控制进程管理脚本进程。控制进程不执行应用代码，即使业务脚本占满自己的事件循环，仍可接收取消并结束脚本；主服务连接断开时也会结束脚本。主机在脚本实际退出后才接受完成结果，并等待已进入宿主的 SDK 文件操作收尾后释放租约。没有运行中的任务恢复队列。

运行器沿用当前 Node 可执行文件，不执行 npm 安装脚本。脚本进程使用 Node 文件权限参数：只读本轮发布代码快照，可访问自己的 workspace，并按用户授权读取／写入选定路径；不继承宿主的模型凭证、登录 Cookie 或整个环境变量。宿主 SDK 另做引用范围、真实路径、能力与身份检查。

这不是完整安全沙箱。Node 官方明确说明其[权限模型](https://nodejs.org/docs/latest-v24.x/api/permissions.html)用于限制可信代码意外访问资源，不提供抵御恶意代码的完整保障；本轮不把它称作操作系统级隔离，也不增加通用桌面鼠标／键盘控制。

当前资源边界：每应用一个运行、本机最多 4 个同时运行，单轮最长 30 分钟；参数合计 512 KiB，单项步骤输入输出及最终结果 1 MiB，文件读写及单个文本产物 16 MiB，每轮最多约 2500 条事件。大数据应保存在文件或产物，不塞入节点 JSON。SDK 单条日志过长明确标注截短，进程控制台最多记录 32 KiB并说明限制；结果和业务数据不会通过截断伪装为完整成功。

## 接口与源码检查入口

`/api/automation/apps/<id>/runtime`：GET 的 `mode=config|runs|run|value|artifact` 分别读取配置、运行列表、本轮事件、引用数据和产物；`run` 支持 `after` 事件序号增量读取。POST 的 `action=save|grant|start|stop|answer` 对应保存、文件选择、启动、停止、回答。请求绑定当前 ownerKey 和 runtimeId；修改及启动再核对应用修订号、配置修订号与运行 ID。

前端每次只合并当前运行的新事件。切换应用、切换运行或页面卸载后丢弃迟到请求，不把旧结果插入新画布。历史运行保存自己的流程及结果列；刷新不生成新运行 ID。

已补充真实脚本事件／产物、相同运行 ID 不重复执行、非响应进程停止、只读文件权限和参数类型的测试源码，未执行。需要检查时由用户自行运行：

```powershell
node --experimental-strip-types --test lib/automation-app-runtime.test.mjs lib/automation-app-package.test.mjs lib/automation-app-store.test.mjs
```
