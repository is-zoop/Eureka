# 浏览器环境与任务页面（v0.88）

2026-11-04：源码已调整，等待用户验收。未执行编译、类型检查、测试、模型调用或实际网页验证。

## 使用方式

- 浏览器环境保存登录、Cookie 和密码保存设置；同一 Eureka 用户选择相同环境时共享这些资料。
- 每次自动化运行的每个网站创建独立页面，以用户、运行、网站和环境代次识别。新任务不会覆盖旧任务的地址、输入和查询结果。
- 切换任务只切换右侧展示的页面；重新显示已有页面不会导航到入口或重新执行查询。浏览器内部的跳转仍保留在所属任务页。
- 关闭网站只关闭对应任务页。最后一个普通环境页面关闭时，宿主保留空白环境页以维持进程内会话 Cookie；新任务仍创建新页面。临时环境不共享其他任务的登录，明确关闭后清理。
- 当前只有一个右侧展示区域，没有新增标签栏。原生网页自动化仍要求所属页面可见；切到其他任务后，原任务的页面和脚本状态保留，等待回到它的会话继续。此改动不声称隐藏页面可以并行执行网页操作。
- 用户主动退出网站账号会影响共享该环境的其他页面，和普通浏览器一致。清除登录／删除环境也作用于该环境的全部页面；其他环境不受影响。

## 实现约定

1. `automation_browser.rs` 分开保存当前展示页与非展示任务页。非展示页保留文档和身份，但撤销控制令牌；旧页面的延迟关闭／隐藏／续期不能作用于新页面。
2. 同一用户、环境和代次的页面共享宿主已有的环境文件租约及 WebView2 资料目录。跨进程占用与清理保护仍保留，不能通过删除锁文件强行接管。
3. 服务端移除全局单网页运行槽，网页会话 ID 纳入网站 ID。每次运行仍保留独立命令队列、一次性执行凭证及结果不明时禁止重复提交的规则。
4. 聊天中同一应用的不同运行采用独立工作区和运行租约，临时输入不覆盖默认配置。目录／旧应用的既有工作区保持兼容。清理、卸载、网页环境设置检查全部未结束运行。
5. 自动化目录的浏览器桥明确绑定界面当前选中的运行 ID，不能再从同一应用的多个运行中任选一条。关闭桥或切换页面不停止服务端脚本。
6. 登录资料仍在宿主用户目录，未复制到应用包或导出物。服务重启不自动重放旧任务，桌面程序退出后不能恢复旧页面 DOM。

## 用户编译与验收

本轮改动包含 Rust，需要关闭旧 Eureka 程序后自行编译、启动新程序，同时重启开发服务并刷新界面：

```powershell
cd E:\Eureka\desktop
.\node_modules\.bin\tauri.cmd build --debug --no-bundle --config src-tauri/tauri.dev.conf.json
```

若旧程序仍占用 `eureka.exe`，先完全退出它再编译。

| 操作 | 预期 |
| --- | --- |
| 会话 A 使用已保存的网页应用，选择默认或自定义浏览器环境并完成登录；在一个可等待／暂停的步骤保留页面 | 页面及任务状态保持 |
| 新会话 B 使用同一应用和同一环境 | 打开独立页面，复用有效登录；不因 A 的内部页面存在而报账号占用 |
| 在 B 中改变筛选条件或进入另一页面，再回到 A 并继续 | A 显示自己的地址、条件与页面；恢复显示本身不重复查询 |
| 再回到 B 并继续 | B 显示自己的页面；隐藏期间等待的网页步骤继续使用 B 的页面 |
| 关闭 B 的网站，再回到 A | A 页面和登录仍在；B 的关闭回调不关闭 A |
| 关闭全部网站后，新建任务 C，选择同一普通环境 | 使用新页面；网站登录未失效时继续复用。网站主动失效时仍需用户登录 |
| 同一次运行依次访问两个已声明的网站 | 网站页面 ID 不同；切回前一个网站保留原文档 |
| 两个会话运行同一文件应用 | 临时工作区分别保存；停止其中一个不会解除另一个的清理保护 |
| 设置中清除某环境的登录，再重新运行 | 该环境重新登录；其他环境的页面和登录不被清理 |
| 临时环境任务在切换后返回，再明确关闭 | 切换保留原页面，关闭后不将临时登录复用给新任务 |
