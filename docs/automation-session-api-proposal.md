# 自动化复用网页登录会话调用 API

2026-11-06：下文保留最初方案背景。Cookie 会话 API 现已接入源代码，实际 SDK、限制与验收步骤见 [自动化会话 API](./automation-session-api.md)。使用前需要更新桌面原生程序；尚未完成真实网站业务验收。

## 原方案中的状态

侧边栏使用原生 WebView2 和已有浏览环境保存登录。自动化的 `ctx.browser` 目前开放连接、页面读取、定位、点击等 DOM 操作；应用工作进程没有宿主提供的 Cookie 读取或通用 HTTP 请求接口。

因此，“浏览器保留登录”和“自动化脚本能够复用 Cookie 调用 API”是两项不同能力。现有提示不意味着侧边栏一定没有保存 Cookie。

本机当前 Tauri 依赖已提供 Webview 的 `cookies_for_url` 原生方法；可由宿主按目标 URL 获取匹配的会话 Cookie，不依赖 `document.cookie`，也不需要用户复制登录凭证。

## 建议接入方式

1. 用户仍在侧边栏登录；应用引用所选浏览环境和网站，不保存创建者的 Cookie。
2. 应用声明 API 的目标域名、路径、方法和操作用途。接口可以跨网站子域，但必须单独声明，不能把所有请求都按页面同源处理。
3. 新增宿主请求 SDK，例如 `ctx.api.request(接口ID, 参数)`：原生层按目标 URL 获取 Cookie，本地请求模块注入凭证并执行原有 API 调用。脚本得到响应业务数据，AI 不接触 Cookie 明文。
4. 现有工具的请求函数接入该适配器，保留原接口参数、结果解析和流程判断，不强制改为页面点击。若现有本地库必须接收 Cookie，可由本地宿主适配器在内存中传入，不写入发布包、聊天或日志。
5. 登录失效时返回需要登录的状态，在侧边栏处理后由用户继续。接口返回的新 Cookie 应同步回同一浏览环境；响应中的凭证头不作为结果暴露。
6. 读取 Cookie 与派发请求前继续校验用户、运行、应用版本、浏览环境和授权范围。跨域重定向不转发原 Cookie；写操作复用持续授权和结果验证，结果未知不自动重试。

查询既可以使用 GET，也可以是接口实际要求的 POST，不能只按 HTTP 方法判断是否会修改业务数据。库存、价格、预售时间等 API 变更应如实声明 effect:mutation 和 browser.write，由脚本按接口业务返回判断结果，无需额外授权问答或页面核对。

Cookie 不能代替所有鉴权：动态签名、CSRF Token、独立账号密钥等仍需按照原接口的方式处理，不承诺登录一次就能调用任意接口。

## 改造范围

- 原生浏览器：受控读取匹配 URL 的 Cookie，维持浏览环境身份和会话状态。
- 宿主运行器：请求声明解析、域名／路径／方法校验、凭证注入、取消、超时及响应脱敏。
- 创建与聊天：增加相同 SDK、探索证据和鉴权失败状态；不把未接入能力描述成已支持。
- 验证：按业务响应核对查询结果；写操作检查最终状态，不以 HTTP 200 作为通过标准。
- 分发：代码包只保存接口规则与环境引用，安装者使用自己的登录；本机凭证与应用代码分离。

这部分涉及 Rust 原生改动，需要更新桌面程序后验证登录和请求。最初方案阶段未修改原生代码；后续实现与测试状态以新的会话 API 文档为准。

## 本轮已实现：创建卡片刷新

“自动化应用”卡片右上角增加组件库刷新按钮。重新读取当前草稿与状态，并在代码摘要不变时同步登记修订号；实际代码已变化时保持冲突提示，不覆盖代码、不沿用过期校验。

刷新保留填写的名称、展开状态、探索证据和试运行记录，不启动、重试或停止自动化。正在运行的预览不重载执行；空闲预览可以重新读取配置和历史。

用户验证：

1. 刷新 Eureka 页面后，检查卡片右上角的刷新图标和悬停说明。
2. 提示“应用已变化”时点击图标，检查最新状态；代码相同的登记变更可恢复，实际代码冲突仍应说明原因。
3. 名称编辑和展开的预览保持；运行中刷新不应产生新运行、额外请求或丢失证据。
4. 切换会话后，迟到的刷新或轮询结果不能覆盖当前会话卡片。

本轮无需重新编译桌面程序；未运行编译、测试或真实网页登录验证。
