# 自动化应用通过组织插件分发

2026-11-02，v0.75。代码接入完成，等待用户验收；未运行编译、测试或真实安装。

## 使用方式

1. 在自动化应用菜单中选择“导出应用包”，保存 ZIP。
2. 将 ZIP 上传到 Haze，类型仍选 **插件（Plugin）**。Haze 发布版本必须与包内 `plugin.json`、`package.json` 一致。
3. 其他用户从现有组织扩展页面安装。安装成功后，打开“自动化”，应用自动出现在左侧目录，无需再次导入 ZIP。
4. 安装者填写自己的参数、选择本机文件与浏览器环境。登录和首次网页变更授权沿用当前用户的宿主流程。
5. 更新、启用、停用和卸载都在原组织扩展管理入口完成。自动化目录负责配置、运行、日志、结果和导出，不再为组织安装提供另一套生命周期按钮。

这是服务端与前端修改，无需重新编译桌面程序。先重启当前 Eureka 开发服务，再刷新页面；无需重新生成已有应用的声明。

## 包的识别与隔离

安装器读取 `plugin.json` 中已有的 `extensions.com.eureka.automation`，按通用应用包规则校验入口、UI、流程、能力和发布文件清单。普通 Skill／HTTP MCP 插件保持原格式；声明了自动化却不合法的包直接拒绝，不降级为普通插件。

市场类型和安装记录始终为 `Plugin`，不新增“自动化类型”。应用登记内部记录所属组织插件，以现有插件登记为启停、版本和卸载的依据。自动化应用不加入首页的普通插件调用菜单，也不作为 Skill 或 MCP 加载；运行入口在自动化目录。

安装和目录扫描只读取声明、校验并复制发布文件，不执行入口脚本、不安装依赖。更新产生不可变代码版本；运行中的任务继续使用启动时的代码，新运行使用插件当前登记版本。来源安装被停用或卸载后，其运行权限失效，不自动重试网页变更。

用户配置、文件授权、浏览器环境选择、运行日志、产物和证据保存在宿主的 `app-data/<用户摘要>/<应用ID>/`；登录和模型凭证仍由宿主保存。代码包与这些目录分离，导出只读取已校验的发布清单，不递归压缩工作区或用户数据目录。卸载默认保留安装者自己的数据，重新安装同 ID 应用可以继续使用。

包中只允许发布声明、代码、流程、规则、资源和说明；额外夹带配置、授权、登录、日志和结果路径会被拒绝。生成器已有的真实样本／凭证检查继续生效。文件清单校验不能识别任意手写源码里的全部隐私，代码和说明也不得硬编码创建者账号、密钥或真实测试输入。

## 多个安装范围与冲突

- 同一组织来源、插件能力 ID、应用 ID 在全局和项目安装时，自动化目录只登记一个应用。使用仍启用且受信任的来源中的最新版本；停用或卸载其中一个来源不代替其他来源的管理操作。
- 正在运行的任务绑定启动时授予权限的安装范围；移除该来源后，不借用另一范围继续运行。所有来源均停用时禁止启动；全部卸载后从自动化目录移除。
- 普通 Skill／HTTP MCP 插件原有的项目覆盖全局规则保持不变。
- 同一应用同版本的代码摘要不同，或不同插件占用同一应用 ID，拒绝登记。修改代码需要提升版本。
- 如果发布者本机已有同 ID 的个人应用，安装组织版本前先从原应用菜单卸载个人登记，数据保留；不会静默覆盖个人应用。
- 插件登记与自动化登记失败会尝试回滚；目录刷新会重新核对来源状态。用户切换 Haze 账号后，按新身份建立独立数据，不读取上一用户的配置和授权。

## 用户验收

| 操作 | 应看到的结果 |
| --- | --- |
| 用另一位用户安装已导出的包 | 扩展中显示“插件”；自动化目录出现应用；没有创建者参数、文件授权、浏览器选择、日志或结果 |
| 安装后打开目录、查看详情 | 不自动运行脚本；在配置完成并点击运行后才执行 |
| 使用安装者自己的网站账号运行 | 使用自己的登录状态，网页变更按自己的账号和声明范围授权 |
| 发布同 ID 的较高版本，并从扩展更新 | 目录使用新版本，安装者配置保留；不替换已启动任务的代码 |
| 从扩展停用，再尝试运行 | 应用不可启动；原来源的活动任务中断；重新启用后可再次运行 |
| 从扩展卸载 | 没有其他来源时目录入口移除；默认保留用户数据，可在确认框勾选删除当前账号的数据；其他范围仍安装时拒绝删除共享数据 |
| 同时安装全局／项目包，移除其中一个 | 目录不重复；剩余来源仍可使用，原来源的活动任务不借用新来源授权 |
| 普通 Skill／HTTP MCP 插件安装和调用 | 继续走原有确认、加载、认证和管理流程 |

需要选择安装范围或确认新认证地址时，保留原确认步骤。服务端的准备令牌、有效期、包摘要和身份绑定继续校验；同一准备令牌不会因页面重绘重复自动提交。安装失败不自动重试，用户点击“重新加载”后重新准备；实际错误由原安装入口报告，避免再增加一条相同失败的通用错误通知。

用户刷新页面后验证：

1. 在全局或项目目录安装无额外确认项的自动化插件，应显示进度并直接完成，无需再点“确认安装”。
2. 安装需要确认认证服务地址的普通插件，应先展示地址与确认选项，未选中时不能安装。
3. 安装失败时，应保留实际错误，并允许重新准备；不自动反复安装。
