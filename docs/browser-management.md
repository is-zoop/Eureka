# 设置：浏览器管理

2026-10-31：在设置侧栏新增“浏览器管理”，等待用户验收。

## 入口与功能

- 入口：Eureka 设置 → 浏览器管理。
- 默认浏览器：保留原有登录数据，支持密码保存提示开关、清除登录数据；不能删除默认环境。
- 独立浏览环境：展示当前用户已有的环境；支持新建、密码保存提示开关、清除登录数据和删除。新建只登记环境，不自动打开网页或登录。只保存输入网址的 origin，不保存其中的路径、查询参数或片段。
- 自定义环境右侧“…” → “编辑浏览环境”可修改名称、网站。默认浏览器的信息固定，不提供编辑。保存不改变环境编号，不删除已有登录；网站改变后原网站应用需重新选择匹配环境。修改期间环境不能被浏览器占用。
- 不展示操作成功横幅；保存后直接更新列表或开关，操作失败仍展示原因。顶部新建按钮与模型页使用相同的小尺寸、字号、间距和图标规格。
- 密码提示由内置浏览器处理；关闭开关不删除已有密码。页面和 AI 均不读取密码、Cookie 或浏览器资料目录。
- 清除登录和删除环境先确认。环境正在使用时禁止从菜单清除／删除，先回到应用点击侧边浏览器的 ×，再打开设置刷新。隐藏面板不会释放占用。
- 延迟清理的旧数据单独展示，可重试清理，不把“已重置环境”表述为旧文件已全部删除。
- 工具使用哪个环境仍在运行页“配置 → 浏览环境与授权”选择。管理变化后，已打开的环境选择器重新读取列表；原选择被删除时明确提示重新选择，不假装已切换到默认浏览器。重置后仅旧代数据待清理的有效环境仍可选择。
- 页面只面向桌面内置浏览器；在普通网页中展示桌面使用提示。登录身份在读取和操作时核对，不与应用包一起保存。

## 样式与实现

使用现有 `SettingsLayout`、`SettingsSection`、`SettingsCard`、`SettingsRow`，沿用设置页面的宽度、标题、间距、圆角及唯一页面滚动容器。交互复用 Button、Input、Switch、DropdownMenu、Dialog，补充中英文翻译。初版复用已有账号管理原生命令；2026-10-31 后续新增原生命令的 update 操作，持有环境锁后保存元数据，原生端同样禁止编辑默认环境和已占用环境。未改变原生权限或浏览器资料结构。

## 用户验收步骤

后续的编辑功能需要重新编译桌面程序。先退出 Eureka，避免 EXE 被占用，重启根目录开发服务，再自行执行：

```powershell
cd E:\Eureka\desktop
.\node_modules\.bin\tauri.cmd build --debug --no-bundle --config src-tauri/tauri.dev.conf.json
```

打开新生成的 `E:\Eureka\desktop\src-tauri\target\debug\eureka.exe`。

1. 打开设置，点击“浏览器管理”，确认标题、卡片、间距、深浅主题和窄窗口与其他设置页一致，页面只有一处整体滚动。
2. 确认默认浏览器和之前的独立环境都在列表中；切换密码保存提示开关，离开后再进入确认保存。关闭开关不应主动清除已有登录或密码。
3. 新建测试环境，填写名称与完整网址；到任一对应网站应用的“配置 → 浏览环境与授权”确认可选，保存环境后在侧栏完成登录。
4. 关闭该环境的侧边浏览器，返回设置刷新，用测试环境验证“清除登录数据”的取消和确认；重新打开需要登录。不要用日常环境验证清理。
5. 删除测试环境，确认默认浏览器没有删除入口。使用已删除环境的工具需要另选环境；原有其他环境、应用代码与工具运行数据不受影响。
6. 若出现待清理项，关闭占用浏览器后点击重试；环境使用中不应允许从菜单清除／删除。
7. 普通网页打开时提示在桌面管理；未登录 Haze 时提示登录，刷新后只能看到当前用户的环境。
8. 在测试环境的“…”中编辑名称及网站，取消不保存；保存后离开重进仍显示新信息。仅改名称时工具的环境选择和登录仍保留；改网站后仅在匹配网站的工具配置中显示。默认环境没有编辑入口。
9. 密码开关保存后直接显示新状态，不出现图中的成功横幅；顶栏“新建浏览环境”与模型页“添加服务商”按钮高度、字号一致，按钮宽度随文案变化。
