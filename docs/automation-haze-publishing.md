# 自动化应用发布到 Haze

我的应用菜单 → 发布到 Haze，打开“发布应用”窗口。发布窗口使用当前 Haze 用户的个人服务凭证，先读取 `/api/developer/publish-context` 的权限、分类和上传限制。凭证由服务端即时获取，不进入前端、AI 或应用包。

底部操作按钮依阶段命名为“上传应用”“提交审核”“发布应用”，可用时保持黑底白字，不随主题反转；不可用时沿用 Button 组件的淡化禁用样式，不能点击。底部所有按钮统一为 40px 高度、border-box 并居中对齐，主按钮保留透明边框占位，与描边按钮对齐。各阶段原有的权限、禁用条件和提交逻辑保持不变。本次仅调整文案和样式，刷新后由用户验证，未执行编译、测试或实际发布。

1. 在“编辑应用”维护名称、图标、分类、标签和描述。每次打开发布窗口，先在后台读取 Haze 状态和最新编辑信息，连接期间不显示弹窗；准备完成后显示完整表单。编辑与发布共用 `AutomationAppMetadataFields` 和标准 Dialog/Field 样式。
2. 顶部固定三个页签：基础信息、快速开始、说明文档；AI 生成按钮位于页签右侧。基础信息按名称/Slug、图标/分类/标签、描述排列，必填字段使用红色星号。两个文档页默认预览，可在各自页面切换编辑和预览。
3. AI 可生成基础信息、Slug、说明文档、快速开始和更新说明。编辑窗口已保存的非空名称、描述、分类和标签逐项沿用；未保存或空白字段由 AI 补全。生成结果刷新或重新打开后保留，不再被未保存的默认值覆盖。AI 使用已校验应用包中的公开内容和用户已配置模型，不读取运行配置、浏览器登录、日志和产物。源码较长时使用标明截断的摘要。
4. 可暂存本机资料，也可保存到 Haze。应用 ZIP、独立文档 ZIP 和可选图标分别上传。应用类型为 `plugin`，包上传与创建指定 `target=eureka`。现有应用导出规则继续生效。
5. 首次操作通过自动化 UUID 查询本人远端应用，再决定创建或恢复绑定。更高版本创建新版本；同版本草稿继续编辑。发布版本来自应用包，不能仅修改表单中的版本号。
6. 保存后明确点击提交审核。刷新可以查看待审核、驳回原因和审核通过状态。审核通过后明确点击正式上架；不会自动送审或自动上架。成功、失败、审核反馈和恢复提示使用全局 Alert 通知，不占用弹窗内容。
7. 市场应用先另存为我的应用，生成新 UUID。原组织安装来源及其更新机制不变。

## 状态与恢复

发布资料位于 `~/.pi/agent/eureka-publications/<用户摘要>/<应用UUID>/publication.json`，独立于代码包和运行数据。记录绑定 Haze 地址、用户、应用 UUID、远端 ID、上次保存摘要、资料基线和待恢复请求。运行数据清理或应用 ZIP 导出不会读取这些记录。

修改、提交审核和发布携带 `base_revision`。每次远端修改前原子保存原始请求和 `Idempotency-Key`，失去响应后只允许恢复该原始请求。明确的 4xx 业务拒绝允许重新准备；连接中断或 5xx 保留请求。远端 UUID、所有者、本地代码和当前登录身份均校验。

已绑定 ID 的读取返回 Haze 资源错误 `4042` 时，再通过当前用户的 `automation_id` 查询恢复绑定。查询成功且未找到应用时，清除旧 ID、远端快照、保存证明与发布基线，保留本机发布资料；找到同用户、同 UUID 的另一个 ID 时重新绑定，但不沿用旧保存／审核证明。只撤销明确指向旧 ID 的待恢复请求；未绑定 ID 的首次创建请求仍须按原幂等键恢复。鉴权错误、未知接口 404、查询失败和网络异常不清除绑定，也不自动上传、送审或发布。

当前 Haze 源码的删除为软删除，`_ensure_automation_available` 仍查询包含已删除记录的 UUID；因此解绑可修复打开窗口报错，但不保证原 UUID 可重新上传。若返回 `40940`，需在 Haze 服务端处理已删除登记的 UUID 占用策略；Eureka 保留应用身份，不通过更换 UUID 绕过。客户端错误文案明确包含这一原因。

Haze 的普通 PATCH 会立即同步展示资料到线上，包括正在编辑的新版草稿。因此编辑已上架资源的现有草稿、或仅修改当前版本资料，需要在窗口明确勾选同步线上资料。创建新版本时通过 `/versions` 一次提交全部资料，不影响旧版展示。

## 依赖与限制

- Haze 需要部署新版后端并应用 `20261105_0017` 迁移；本功能不会代执行 Haze 迁移。
- Haze 当前包和文档上限 10 MiB、图标上限 2 MiB，实际限制以预检查接口为准。
- Haze 当前 `eureka_package.py` 尚未接受多功能应用 `automation.actions` 和 `ui/`、`workflows/` 路径。此类包会显示 Haze 的兼容性错误，需要 Haze 同步校验规则；Eureka 不删除功能声明或降低校验来绕过。
- 旧版已发布应用在本机恢复绑定后，需保存发布资料才能继续送审；不会猜测本机文档与远端文档相同。
- 不自动生成图标；可选择 PNG/JPEG/WebP，或沿用远端已有图标。

## 验证

删除后恢复的用户验收：使用当前已从 Haze 删除的应用，重新打开“发布应用”，应能显示保留的本机资料，不再因旧 ID 报错；原保存／审核状态不能继续当作有效。只有用户点击按钮才上传。若上传返回 UUID 占用，按上面的 Haze 端限制处理。重启开发服务并刷新即可，本轮不需要原生编译。

新增回归源码覆盖旧绑定失效、UUID 重新绑定、权限／网络失败不清除记录、旧 ID 待请求退役，以及首次创建幂等恢复的保留；本轮未执行测试、编译或真实 Haze 操作。

`node --test lib/automation-publication.test.mjs` 使用内存 Haze 接口覆盖上传、版本、审核、归属、请求恢复、AI 输入和资料校验，不连接真实 Haze 或模型。真实凭证调用、审核与其他用户安装仍需联调验收。

上传表单由同一套 Undici `FormData`/`Request` 编码为 multipart 字节，并携带对应 boundary，避免 Next.js 的 fetch 与全局 FormData 来自不同实现时将文件表单发成 `[object FormData]`。`node --test lib/haze-publishing.test.mjs lib/automation-publication.test.mjs` 的 22 项测试覆盖该场景，使用本地 HTTP 接收端核对应用 ZIP、文档和图标的文件名、类型及原始字节；未调用真实 Haze 上传接口。

2026-11-05 检查结果：发布流程、应用包和语言注册相关 20 项测试通过；TypeScript 检查通过；涉及文件 ESLint 无错误，应用管理器原有 `current` Hook 依赖提示仍在。扩展回归的 3 项失败位于本次未修改的文件：文件选择器含未翻译中文、运行界面的静态渲染断言、多功能测试缺少路径别名解析；本次未修复这些并行工作中的问题。未执行真实 Haze 上传、审核或上架，也未运行 `next build`。
