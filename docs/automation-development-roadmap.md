## 1. 我们要做成什么

让没有技术背景的同事，在自己电脑上的 Eureka 中描述任务、提供网站并登录，由 AI 探索网站，生成并验证自动化工具。工具保存后可以重复运行，也可以打包上传 Haze，让其他同事从企业扩展安装，并使用自己的账号运行。

典型使用过程：

```text
用户描述需求并提供网站
  → 用户在 Eureka 浏览器中登录
  → AI 研究页面与操作方法
  → AI 生成工具，先用少量数据验证
  → 用户确认结果，保存到“我的自动化”
  → 下次填写参数或上传文件即可运行
  → 打包插件并上传 Haze
  → 同事安装、登录自己的账号、运行
```

“支持任意网站”指允许用户提供新的目标网站，不预先限定为已封装的平台；不代表保证所有网站都能自动完成。验证码、特殊验证、权限不足或复杂业务步骤需要明确暂停并允许人工协助。

## 2. 已确认的方向与现有基础

### 已确认的产品方向

- 每位同事在自己的电脑上运行 Eureka。
- 用户可以提供新网站，由 AI 从探索到生成自动化。
- 已跑通的工具应当保存、修改、重复使用。
- 工具后续应能打包上传 Haze，通过企业扩展安装分发。
- 每完成一个可测试功能，用户会实际测试；测试期间可以调整功能和开发顺序。
- 本文只制定开发计划，不代表授权一次性实现全部阶段或发布插件。

## 3. 每次开发和测试的规则

1. 从当前里程碑中选一个功能编号，例如 `M01-F1`，写清本轮范围和用户看得到的变化。
2. 先检查现有实现与工作区改动；能复用的直接复用，不覆盖其他工作。
3. 完成实现及必要的开发自检，并把该功能标记为“待用户测试”。
4. 交付具体测试入口、操作步骤、预期结果和已知限制。开发者自检不能代替用户验收。
5. 用户测试后，记录实际结果；失败则修复当前功能，需求有变化则先更新计划。
6. 用户确认通过后才标记“已验收”，由用户决定继续哪一项。不因为代码写完就自动推进后续里程碑。
7. **2026-10-29 用户明确的协作边界：** 人工验证由用户执行，交付入口、步骤和预期结果；需要编译时提供命令交由用户执行，不主动编译、打包或启动浏览器/桌面程序做人工验证。本轮仅编辑和阅读代码，没有运行编译、检查命令或自动 UI 验证，避免耗时。后续如需这些执行步骤，先依据用户授权范围安排。
8. 用户明确要求 M02-F2 与 M02-F3 一起做，本轮合并实现、联合测试；其他阶段仍按原逐功能验收规则推进。
9. 用户随后明确表示 M02 测试稍后进行，要求继续 M03-F1 到 F3；据此合并开发 M03，但不将 M02-F2/F3 标为已验收。M03 依赖已验收的 M01，可先验收人工登录与账号隔离，再联合验证 AI 操作。
10. 用户确认设置居中与状态删除“这一步也没问题”，并授权直接完成 M04-F1～F3，按三项联合交付。记录该界面修复通过，不据此补写未提供的登录持久化/密码保存逐项结果或商品业务值。

状态统一为：`未开始`、`开发中`、`待用户测试`、`需修复`、`已验收`、`暂缓`、`取消`。

一个里程碑包含多个功能。每个功能都可以单独开发、单独测试；不要求等整个里程碑完成才交给用户。

### 计划调整规则

- 每次新增、删减、拆分或调整顺序，都更新里程碑内容、依赖关系、状态和变更记录。
- 功能编号保持稳定。取消的编号保留并说明原因，新功能使用新编号。
- 已验收功能保留历史记录。若新需求改变其行为，新增变更项并列出需要重测的旧功能。
- 用户测试期间提出的新想法先记录，不未经讨论扩大本轮实现范围。
- 有依赖的功能不能只修改顺序而忽略前置条件；无依赖的功能可以提前。
- 不预设固定工期。每轮确定范围后，再按实际复杂度估算。

| 功能 | 内容 | 状态 |
| --- | --- | --- |
| M00-F1 | 确定试点网站、业务任务与样例输入；真实账号可用性在 M01 登录验证 | 已验收 |
| M00-F2 | 确定预期输出、人工核对方法和允许执行的操作范围 | 已验收 |

用户已选择首例：[淘宝在售商品数据查询](./automation-pilot-taobao-on-sale.md)，查询商品 `944311760187` 和 `978240175678` 的价格、库存、累计销量和 30 日销量。M00-F1 的“已验收”仅指用户已明确选定任务和输入，不代表网站已登录或数据已查到。已有插件可用于对照结果，但不以“直接复制旧脚本”代替探索能力验收。

通过条件：输入、输出、核对方式明确；开发者不需要猜测业务含义。

### M03：网站登录与浏览环境复用

目的：像普通浏览器一样延续用户登录，默认直接使用当前网站账号；有多个店铺需求时再选择独立环境。

| 功能 | 内容 | 状态 |
| --- | --- | --- |
| M03-F1 | 默认持久浏览环境，无需创建账号或绑定；设置界面显示当前环境 | 待用户测试 |
| M03-F2 | 登录恢复、可选浏览器密码保存提示、清除本机浏览数据；过期后人工重新登录 | 待用户测试 |
| M03-F3 | 高级选项提供独立环境和临时会话；保留旧环境与引用、按 Haze 身份隔离 | 待用户测试 |

用户测试：默认环境登录后关闭/重启并继续查询；开启密码保存，在支持的表单上选择保存/拒绝；网站内换账号；按需切换独立环境；验证临时模式与数据清理。

通过条件：普通使用无需先创建账号；默认及独立环境关闭后保留登录，临时模式仍清理；密码交给浏览器管理，原始 Cookie/密码不进入模型或插件。默认环境同一网站的当前登录共享，换账号影响该环境中的任务；不同 Haze 身份、独立环境之间隔离。

默认草稿没有账号引用，使用当前用户的默认浏览器。高级模式仍可在草稿保存独立环境引用；M06 工具库沿用选择契约，分发时不携带登录环境。取消上次人工确认状态及每次确认按钮，以操作前提醒核对实际店铺替代；不声称自动识别任意网站登录有效性。

### M04：网站探索与请求分析

目的：让 AI 识别网页操作背后的真实方法，并保留证据。

| 功能 | 内容 | 状态 |
| --- | --- | --- |
| M04-F1 | AI 开始操作时自动记录查询相关请求，随暂停/结束停止，详情中查看脱敏证据 | 正常场景已验证；异常场景未补验 |
| M04-F2 | 查询完成后自动分析参数、业务字段、分页和凭证限制，校验引用；分开说明请求限制、响应失败及字段缺失 | 正常场景四指标已识别；其他分支未补验 |
| M04-F3 | 直接请求或网页查询动作复查相同编号，比较两次真实响应；完整一致才通过，保存执行模式，不要求第二编号 | 用户截图四项比较一致；总状态及保存待确认 |

用户测试：让 AI 完成一次指定编号查询，检查后台自动记录、自动分析、同一编号请求复查和字段比较；不需要为了录制再操作一遍，也不需要第二个编号。

通过条件：请求源于本轮 AI 实际操作，原查询响应与同编号复查的所需业务数字字段完整且一致才显示通过；HTTP/业务失败、字段缺失、隐藏或截断数据不能通过。不虚构接口，不把一次输入的一致性说成跨编号泛化能力；无法复用时明确显示无法验证。

范围说明：允许人工示范；探索写入操作前需要明确测试对象和范围。网页内容作为数据处理，不能替用户扩大操作权限。

本版复查留在当前浏览器账号下，不开放服务端任意 HTTP。带签名/临时令牌、POST、跨源等不能直接复用时，可重放此前实际执行过的明确查询动作，由网站生成新凭证并发送请求；必须捕获到相同接口、相同编号的新响应，不以旧页面或第二编号示范代替校验。探索证据保存执行模式，生成可运行工具仍属于 M05。

### M05：生成并验证第一个工具

目的：把探索成果转换成能够接受不同输入的可运行工具。

| 功能 | 内容 | 状态 |
| --- | --- | --- |
| M05-F1 | 受控工具格式：名称、版本、编号输入、查询控件、字段映射、结果与浏览器要求 | 已实现；用户确认整体运行通过 |
| M05-F2 | 从通过的证据生成工具，在当前登录浏览器逐个查询 1～3 个 ID | 用户确认运行通过 |
| M05-F3 | 按商品 ID 展示数字，区分无结果、缺失、失败、不确定与取消，支持重试和重新生成 | 已实现；正常运行通过，异常分支待具体反馈 |

首版采用固定运行器和声明式配置：填入编号 → 点击已确认的查询按钮 → 从对应新响应按商品 ID 读取字段。网站自行处理登录、签名和跨源请求；模型不生成任意执行代码。每个创建草稿暂存一个工具和最近一次运行，完整工具库、参数文件和版本管理留在 M06，较大批量和断点恢复留在 M07。

用户测试：运行至少两组不同输入，包含正常编号、无结果编号和错误输入；与人工结果或已有插件对照。

通过条件：结果正确、输入可替换、错误可解释；不能仅凭 HTTP 成功或进程退出码判断业务成功。

### M06：保存、重复运行与修改

目的：用户不需要每次重新解释需求，也不需要读代码。

| 功能 | 内容 | 状态 |
| --- | --- | --- |
| M06-F1 | “我的自动化”列表、工具详情、命名和保存 | 用户确认验证完成 |
| M06-F2 | 根据参数定义生成表单，支持所需的输入文件与结果下载 | 用户确认验证完成；首版 ID / CSV / TXT 范围 |
| M06-F3 | 按按钮或通过聊天调用同一个已保存版本 | 用户确认验证完成 |
| M06-F4 | 用户用自然语言修改工具，验证后保存新版本并保留旧版本 | 部分实现待测试：调整后另存独立工具；完整版本历史未开始 |

F1～F3 用户测试：保存后刷新/重启找到工具，换参数或导入 CSV/TXT 运行，下载 CSV；从新聊天调用同一工具并核对实际结果。首版沿用 1～3 个不同编号，Excel 可另存为 UTF-8 CSV。F4 后续再测试自然语言增加列/条件、修改验证和新旧版本保留。

## 6. 暂不作为首版前置条件的能力

以下保留为候选，不阻塞第一个工具或第一个 Haze 插件：

- 拖拽式流程编辑器。
- 跨多个网站的复杂流程。
- 定时任务与无人值守运行；本机关闭时需要另外的执行环境。
- Eureka 内一键上传 Haze；先核实服务端接口与权限。
- 完整迁移 `E:\synthos_plugins` 下全部旧插件。
- 自动探索并绕过所有验证码或网站限制。
- 多人协作编辑、集中执行服务器和企业审批流程。

若某项成为试点任务的必要条件，应通过变更记录提升优先级，而不是默默加入本轮开发。

4. 换一组输入后仍可运行，不能只支持制作者的固定样例。
5. 若任务涉及分页或批量，明确总数及成功、失败、无结果项目，能核对是否遗漏。
6. 业务数值、账号样本和导出文件保存在本机测试位置；仓库文档仅记录脱敏规则和验收结论。
