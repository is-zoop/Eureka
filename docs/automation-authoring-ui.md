## 修改入口的输入框预填（v0.70）

用户要求首页标题／说明／模式标签不再按修改对象改写。恢复普通欢迎标题与说明、普通输入提示和“自动化 ×”标签，删除 v0.69 动态标题、名称版本标签和相应文案。应用关联、用户与版本检查、错误阻止发送及重新载入保持。

在原应用关联已验证、首页尚无消息且输入框为空时，将 `基于现有的自动化 “{应用名称} v{原版本}” 修改：` 作为可编辑的真实草稿文字填入，末尾换行并聚焦光标。名称来自已授权应用详情，版本来自任务的原版本引用。复用输入框已有的 insertIfEmpty 实现，普通命令补全调用行为不变；同一输入框中按任务 ID 只处理一次，不覆盖提前输入的文字，删除前缀／发送／恢复上下文时不反复填入。不会自动发送、生成或运行工具。

本次不涉及原生代码；刷新后从应用菜单重新点击“用 AI 修改”验收。未执行编译、类型检查、测试或网页验证。

验收：普通欢迎页和自动化标签保持原样；输入框出现对应应用／版本前缀，光标在末尾；用户可补充并发送修改要求；清空前缀后等待数秒不反复插入；下一条消息不自动加前缀；若用户已提前输入内容应保留；A/B 应用预填内容及后台关联分别正确。

## “用 AI 修改”的首页入口（v0.69）

用户反馈点击应用菜单“用 AI 修改”后只出现普通首页，没有修改对象。入口原先仅依赖 sessionStorage 的一次性标记，新对话的项目根目录初始化可能重置 draft key；标记未命中或恢复失败后，hook 静默退为普通聊天。

现在由 AppShell 向 ChatWindow／现有 useAgentSession／useAutomationMode 直接传递按 draft key 绑定的导航意图，sessionStorage 只作刷新备用。同一 cwd 的项目根目录初始化不重建新对话；未消费的意图随新草稿目录键转换，读取成功后确认消费，退出后不因项目切换复活。重叠恢复请求按序号舍弃迟到结果；刷新或移交意图时保留同一任务引用，不依赖本地存储写入成功才能保持关联。

v0.69 曾使用动态欢迎标题和应用名称／版本标签，v0.70 已按上节改为输入框预填。标签仍可退出，普通对话与手动 `/automation` 创建保持原行为。名称是说明文字，关联使用应用 ID／revision／version；服务端原有原应用版本验证、工作区复制与新版本保存不变，不能凭 UI 名称改另一应用，也不会自动执行或直接覆盖原包。

加载时核对当前 Haze 用户、登录代次、原应用 ID 和版本，名称取已授权详情接口。加载期间／加载失败禁止发送，失败显示内联“重新载入”，保留输入；hook 的提交入口同样拦住，不能降级为普通聊天。工具全部关闭和计划模式的权限边界继续有效。

本轮仅改前端和共享类型，无需为这些改动编译桌面程序。重启开发服务并刷新；未运行编译、类型检查、测试或真实模型／网站验证。已补原应用引用与 UI 元数据分离的回归测试源码，未执行。

用户验收：

1. 在应用 A 菜单点击“用 AI 修改”，首页应自动预填 A 的名称和当前原版本，不需要手动选应用所在项目或再次选择自动化命令。
2. 描述一条修改，AI 应读到 A 的原代码与需求；保存时仍由新版本流程验证，原工具不因打开页面被改变。
3. 刷新尚未发送的修改草稿、切换项目目录，确认修改对象没有变成普通聊天或另一个应用；退出修改再切换项目，不应重新进入已退出的任务。
4. 在应用 B 重复入口，预填内容和后端原版本应均属于 B，不能串用 A 的草稿或证据。
5. 详情暂时不可读取时，应显示错误和重新载入，发送不可用且输入保留；恢复后能继续原对象，不能以普通聊天提交。
6. 新建普通对话、手动选择自动化、退出模式、计划模式及关闭全部工具仍按原规则工作。

## 界面与保存

- 删除首页对话顶部的自动化说明条，保留输入框模式标签和旧历史只读提示。
- 卡片默认展示应用名称、输入参数、输出内容、实际试运行和结果校验；版本、支持范围、限制与校验明细放入“详细信息”。已有会话消息不重写。
- 当前展示采用轻量文字布局：字段名称加粗并使用主文字色，内容以常规字重与次级文字色显示，移除内容框、底色和只读输入框。保存后的应用名称为普通文字；保存前仅名称保留下划线编辑入口。“详细信息”与主体使用相同的文字层级，以细分隔线及整行展开标题衔接，操作按钮位于底部。窄内容区字段改为单列。
- 名称在保存前可填写或修改，保存后显示实际安装名称。名字限制为去除首尾空白后的 1～100 字，不接受换行及控制字符。
- “预览应用”在对话中展开正式页面的同一个 `AutomationApplication`，共用配置、浏览环境、画布、拖拽分栏、步骤输入输出、结果、日志及下载；移除原 compact 分支。使用非模态区域，避免挡住原生侧栏。
- 预览固定本任务候选的运行 ID，无直接启动或历史切换入口；展开／收起不重跑。实际执行与校验继续由原 Pi loop 的任务工具负责，等待回答时自动展开。
- 文件选择从“预览应用 → 配置”完成，登录、首次授权、澄清和停止保留。

保存时仅替换发布包 `plugin.json` 中的显示名称，不改变业务脚本、参数、流程、权限、AI 规则或其他文件；包格式会重新检查。原校验保持绑定实际试运行的源摘要和运行 ID，保存前确认源包未变，并在保存意图中分别记录源摘要、发布摘要和实际名称，兼容旧记录及中断重试。运行记录不重写，代码变化仍要求重新校验。UI 名称不得被业务脚本当作业务输入。
