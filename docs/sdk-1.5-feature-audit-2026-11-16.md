# Pi SDK 1.5.0：Eureka 可补充功能清单

对照日期：2026-11-16。Eureka 当前版本：0.8.9。

后续实施：N02、N03、N09、N01、N06 已按用户确认的入口边界接入；当前交付范围、用法和验证见[实施记录](sdk-1.5-feature-implementation.md)。本文以下表格保留实施前的审计结果。

当前补充状态：N07 已接入对话请求生成图片首版；N10/N13 按用户要求暂停；N04/N12 已接入。详见[实施记录](sdk-1.5-feature-implementation.md)，下方原审计表不是当前完成状态。

第二批已重新核对当前源码及本地 1.5.0 安装文件，建议范围、收益、缺口和入口见文末「第二批开发范围复核」。该部分为开发建议，尚未表示功能已交付。

## 对照范围与结论

以当前工作区和已安装的 Pi SDK 1.5.0 源码、类型、文档为准，对照此前的 0.84.1 基线。五个直接 Pi 依赖均为 1.5.0；本次没有升级依赖或修改生产代码。

需要区分三种情况：SDK 已经自动生效；Eureka 已接入底层但缺少设置和展示；需要新增完整产品功能。下表中的候选包含 0.84.1 到 1.5.0 之间的累计新增能力，不全部是 1.5.0 首次发布的功能。

**建议先做 N02、N03、N09、N01，再做 N06。** 前四项完善现有工具和聊天体验；N06 最贴近当前自动化业务。编号沿用旧清单，便于后续逐项处理。

## 第一批的实施边界与验收

### N02：让工具搜索真正用于按需暴露

- 先支持手动 MCP，再单独评估 Haze 服务级策略；不直接把所有现有服务器批量改为 deferred。
- `direct` 适合少量常用工具；`deferred` 在搜索命中后提供工具定义；`codemode` 由脚本发现并组合调用。按需暴露工具定义不等于完全按需建立服务器连接。
- 配置编辑保留 `toolExposure` 等 SDK 支持的已有字段，避免保存时重置高级设置。
- 用同一组真实工具比较首轮工具定义数量、请求大小、搜索命中与调用成功率。减少上下文占用是预期收益，不预先承诺具体比例。
- 验证中文搜索、工具动态增删、重连、权限撤销，以及 direct/resource/Codemode 各入口的 Haze 校验。

### N03：统一等待用户状态

- 接入 SDK `ui_prompt_start` / `ui_prompt_end` 扩展事件，并适配宿主自定义 UI 的 `blocked` 选项。
- 合并现有澄清、自动化等待登录和浏览器授权状态；避免同一等待过程被重复计数。
- 验证刷新、嵌套提示、取消、断线恢复，以及回答后继续执行；等待不误报完成。

### N09：模型和费用展示

- 分开表示用户选择的模型、实际路由执行模型，以及服务商额外报告的 `responseModel`；三者不一定都有值，也不一定不同。
- `totalFromProvider` 表示总额来源，不代表每个输入/输出分项都由服务商报告；不把来源未知的旧记录当作账单值。
- 对 Radius/虚拟模型、普通直连、OpenRouter、混合汇总与旧会话分别验收。
- 保留现有费用记录；本功能展示服务商报告值，不是账户余额或正式账单核对系统。

### N01：Windows PowerShell

- 使用 SDK 原生工具发现和实现，优先 PowerShell 7，按 SDK 规则回退 Windows PowerShell。
- 同步修改权限预设、工具名称校验和任务阶段分类，避免已选工具在重开后丢失或被误分类。
- 用中文路径、带空格参数、UTF-8 输出、非零退出、取消和超时验证；Bash 继续可选。

### N06：自动化分类判断

- 在现有聊天 AI 判断之外增加独立分类操作，保留已有接口参数和业务行为。
- 从 SDK 分类模型目录选择模型；支持 bool / choice / score，图片仅在模型声明支持时可用。
- 验证 `stopReason` / `errorMessage`，不能将空结果或供应商错误当作正常分类。
- 若允许 Codemode 调用分类模型，再按授权、模型范围、并发、取消与费用预算接通模型桥接；不能只删除 `models: false` 就视为完成。

## 第二批与后续注意点

- **N04**：预热可能产生额外请求和费用；SDK 的成本判断不等于保证省钱。增加设置前先展示有效配置，验证受支持模型的实际触发与停止行为。预热用量计入会话用量，不作为用户聊天内容。
- **N07**：生成图片与“模型识别用户上传的图片”是不同操作；按 `image` 模型类型独立选择和保存产物，不混入聊天模型选择器。
- **N08**：虚拟模型 API 在此版本仍标为实验性。优先复用扩展注册；处理模型失效、续跑/重试、分支恢复和实际上下文窗口，不仅是增加一个“自动”选项。
- **N10**：使用显式、局部 span 和本地记录；SDK 不会因为安装了遥测包就自动提供完整的 Eureka 运行看板。它与 CLI 安装统计不是同一功能。
- **N11**：使用 SDK 追加式 context edit，不覆盖原始 JSONL。编辑后验证工具调用/结果配对、分支、压缩、用量估算和恢复；已经发出的上下文不受追溯影响。
- **N12**：读取 npm 扩展的 `pi.changelogPath` 或包根 CHANGELOG，复用扩展中心。组织扩展已经存在的版本历史保留；不要依赖终端启动通知自动出现在网页。
- **N13**：按时间和字节数限制进度，保留最终工具结果为权威输出；嵌套 Codemode/MCP 的结构化内容也需要脱敏。
- **N14**：先补通用 MCP OAuth；Haze 继续使用现有专属认证链路。SDK 1.5 的自动客户端注册不意味着所有服务器都无需客户端信息；退出、撤销、回调和错误恢复仍需实测。

## 第二批开发范围复核

复核日期：2026-11-16。本轮只更新范围说明，未修改运行逻辑、依赖、凭证或用户会话，也未执行计费模型调用。第一批测试结果不作为第二批的验收结果。

### 建议顺序

建议先交付 **N13 → N10 → N12 → N04**。这四项围绕现有 Agent 的执行反馈、问题定位和配置透明度，不扩大 Agent 的业务工具权限。

N14 是有明确第三方 OAuth MCP 接入需求时的下一项；N07、N11 需分别确定图片产物入口和上下文编辑交互，不建议作为上述四项的附带改动。N08 继续保留为后续实验项。

这里的“1.5.0 功能”包括从旧版升级至 1.5.0 后可利用的累计能力。N12 的扩展更新说明和 N14 的 OAuth 注册策略改进属于 1.5.0 更新内容；N04 在更早版本已加入，N10/N13 主要是 Eureka 尚未充分利用的 SDK 能力，不能都称为 1.5.0 首次新增。

| N14 通用 MCP OAuth | 可接入要求网页登录授权的第三方 HTTP MCP，减少手工处理访问令牌 | 原生传输已传递 SDK authProvider，但手动表单没有完整 OAuth 配置、登录和退出入口 | 手动 HTTP MCP 增加 OAuth 配置和登录状态；验证首次登录、过期、取消、退出及重新授权 |
| N07 图片生成 | Agent 可以产出图片供用户保存、后续任务引用；与当前图片识别互补 | 有图片输入，但没有 image 模型选择、生成授权、产物保存与生命周期 | 先决定对话或自动化入口，再单独交付模型目录、生成、预览和产物保存闭环 |
| N11 可恢复的上下文编辑 | 长对话可以暂时移除大段工具输出或替换为摘要，保留可追溯的原始历史 | C05 已完成读取与投影兼容，但没有用户主动编辑的命令、界面和恢复流程 | 空闲会话中显式编辑选定条目；追加 context_edit，支持查看有效上下文和恢复 |

### 前四项的开发边界

**N13：显示真实进度，不改变工具执行。**

- 不重新执行、不自动重试工具，不改变工具超时、取消或权限检查；最终工具结果继续作为权威结果。
- 只有工具实际发送更新时才显示中间进度，不承诺所有 MCP 都有百分比或逐行输出。
- 为每个工具调用限制发送频率、单条长度和缓冲总量，防止大量命令输出拖慢聊天；工具完成后清理暂存数据。
- 刷新、断线和重复事件按运行及工具调用 ID 合并，不把旧运行的进度接到新运行上。刷新恢复优先使用当前进程快照，不将每个增量写进会话 JSONL。
- 沿用 Haze 浏览器交接的脱敏规则，覆盖 MCP 结构化结果和 Codemode 嵌套内容。没有明确安全展示规则的字段不直接发送到浏览器。

**N10：先提供本地、有限的诊断。**

- 第一版只保存耗时、服务商/模型标识、可观察的重试次数、状态和错误类别；不默认保存完整提示词、工具参数、请求头、Cookie、密钥或响应正文。
- 不接第三方遥测平台，不改变 SDK 的安装统计设置；诊断记录不作为 Agent 的业务状态或继续执行的依据。
- 只有 SDK 或服务商实际提供的信息才展示。首个事件不冒充首个文本 token，服务商内部重试不可见时明确不提供次数。
- 使用显式请求上下文关联记录，避免并发会话串用全局 span；请求失败时诊断失败不能遮蔽原始错误。
- 本地记录设数量、大小及保留范围上限；重启后是否保留需在实现中明确。第一版可只支持当前运行时，不承诺旧聊天补齐诊断。
- 不重新增加用户已要求移除的“模型与费用”入口，不新增独立诊断看板。

**N12：展示更新说明，不改更新策略。**

- 按 SDK 的包元数据解析 `pi.changelogPath` 或包根 CHANGELOG；只读已安装、已授权范围内的包，不为读取说明加载或执行扩展。
- 遵循 SDK 的适用范围：包需包含扩展；首次发现版本建立基线，不把所有旧内容当成新更新。缺失、禁用或无法解析更新说明时正常显示包信息。
- 限制文件大小并检查解析后路径、符号链接和 Markdown 渲染边界；不允许包声明的路径任意读取本地文件。
- 不自动升级或重载扩展，不改变用户固定的版本；组织扩展现有版本历史保持原行为。

**N04：提供控制，不承诺一定省钱。**

- 保持现有有效配置，未设置时沿用 SDK 默认 streaming；不自动升级为 idle。界面应标明 streaming 可能在运行期间发送预热请求，idle 也允许在两次运行之间预热。
- 复用 SDK 的全局 cacheWarming 设置，不创建竞争计时器，也不让 dormant 会话为了读取状态而启动 AgentSession。
- 设置为 off 时应停止后续调度并按 SDK 规则取消进行中的预热；不能承诺撤回已被服务商接受的请求或费用。
- 模型不支持缓存寿命、价格或提示大小未知、预期收益不足等情况展示真实未触发原因；不强行发请求证明已启用。
- 检查 SDK usage 条目与 Eureka 汇总关系，避免预热费用重复计入总额；预热请求不作为聊天消息显示，也不加入模型对话上下文。
- 停止会话、切换模型、分支及关闭运行时均验证计时器和请求清理；不新增后台唤醒电脑或定时保活服务。

### 其余三项的边界

- **N14**：先限手动配置的 HTTP MCP；Haze 继续使用现有逐请求个人凭证及身份/URL 校验，不改造成通用 OAuth，不迁移旧凭证。使用 SDK 原生 MCP OAuth 存储、刷新和注册能力；网页登录仍需宿主接通回调、取消、错误和状态刷新，不能只补几个表单字段。`auto` / `dcr` / `cimd` 属于高级设置，并不保证所有服务器都无需注册客户端。
- **N07**：图片模型与聊天、分类模型分开；图片识别不等于图片生成。需要新增明确的调用权限、数量/大小限制、费用记录、取消和产物授权。先不开放 Codemode 的全部非聊天模型桥接，也不改变 N06“仅自动化分类”的既定范围。
- **N11**：只在会话空闲时操作，不修改已发给服务商的请求，不覆盖原始 JSONL；限制到明确支持的条目类型并保证工具调用/结果配对。分支、压缩、运行时有效消息、上下文用量和缓存状态必须一致失效，恢复要通过追加编辑或分支完成。自动生成摘要若需要模型调用，另行明确授权及费用，不默默调用。
