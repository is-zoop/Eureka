## 中文

- 自动化支持一个应用包含多个独立功能：分别保存配置、流程、运行记录和结果，通过统一分体按钮选择运行。
- 首页对话可直接调用自动化、调整配置并逐步执行，返回实际结果；文件选择、网页登录和授权沿用宿主能力。
- 浏览器环境与任务页面分离，同一环境共享登录，不同任务使用独立页面；改进连接恢复和任务生命周期处理。
- 新增应用信息编辑、图标与公开资料维护，以及上传至 Haze、提交审核和发布流程。
- Haze 应用删除后重新查询绑定，保留本地发布资料，并明确显示已删除登记仍占用 UUID 的冲突原因。
- 统一自动化运行页与创建预览的按钮、菜单、选中态及配置表单样式，移除多功能验收包下载入口。
- 修复多功能运行时误用默认脚本入口、实际执行与画布不一致的问题。

Haze 发布需服务端支持对应发布接口和应用包协议。Haze 软删除若仍保留 UUID 登记，重新上传需先由 Haze 处理原登记。

## English

- Added independent actions within one automation application, with separate configuration, workflows, history and results, selected through a shared split button.
- Added direct automation invocation from chat, configuration updates and step-driven execution with actual results, while retaining host file selection, browser login and authorization.
- Separated browser environments from task pages: tasks share environment login state while using independent pages, with improved connection recovery and lifecycle handling.
- Added application metadata and icon editing, plus Haze upload, review submission and publication.
- Recover stale Haze bindings without discarding local publication drafts and explain UUID conflicts involving deleted remote registrations.
- Unified runtime and authoring-preview controls, selection states and configuration styling, and removed the downloadable multi-action acceptance package.
- Fixed selected actions launching the default script instead of their own entry, which caused workflow and execution mismatches.

Haze publication requires compatible server endpoints and package validation. If a soft-deleted Haze registration still reserves the automation UUID, that registration must be handled in Haze before uploading again.
