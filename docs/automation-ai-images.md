# 自动化 AI 节点：复用 Pi 图片处理

2026-11-03：源码接入完成，等待用户验收。未运行编译、类型检查、测试、图片处理或模型调用。

## 调用与兼容

创建阶段继续使用原 Pi loop。保存的应用运行时仍是明确 AI 节点内的一次模型判断，不创建新的聊天，也不附带创建对话历史。模型凭证仍由当前用户的宿主管理，规则、图片输入与严格 JSON 输出继续分开。

新生成的应用优先使用文件引用：

```js
// item.ref 来自 ctx.files.list()；也可使用已选择的 file 字段。
const decision = await ctx.step("classify", { name: item.name }, () =>
  ctx.ai("classify", { question: "判断图片是否含尺码与尺寸的对应关系" }, {
    images: [item.ref],
  })
);
```

- 声明 `ai` 和 `files.read`，流程中的 `classify` 节点必须为 `kind:"ai"`；规则在 `ai/rules.json` 定义。
- 宿主按既有文件授权、目录边界、符号链接检查读取图片。不会因 AI 调用接受任意绝对路径或网址。
- 兼容现有草稿的 `ctx.ai("classify", {image:{mediaType:"image/jpeg",base64:...}})`，也兼容图片对象使用 `mimeType/data` 和 `input.images` 列表。宿主先分离图片，再检查文字大小；图片编码不作为文字发送。
- 第三个参数只接受 `{images:[文件引用或图片对象]}`。两参数文字调用保持原行为。节点输入输出和日志应记录文件名、判断、原图元信息，不要放整张图片编码。

## 复用范围与限制

- 通过 Pi 公开导出的 `resizeImage` 和 `formatDimensionNote` 复用现有处理代码，不复制图片解码器、不增加依赖、不导入 SDK 私有子路径。
- 使用 Pi 默认缩放参数：等比控制在 2000×2000 范围，单图编码约 4.5 MiB 上限，复用方向处理和 PNG/JPEG 压缩策略。处理在宿主侧进行，不修改原图。
- 当前接受 JPEG、PNG、WebP、GIF；按文件头识别格式，内联数据还需与声明匹配。动态图不承诺逐帧识别。
- 每次调用最多 10 张图片，原始图片合计最多 16 MiB，处理后编码合计最多 16 MiB。文字输入和 JSON 输出分别保持 64,000 字节限制；不是把全部输入限制粗暴放大。
- 沿用宿主当前用户的默认可用模型；默认模型不支持图片时，明确要求更换默认模型，不静默换用其他服务商。
- 图片解码／缩放失败、文件授权失效、模型不支持图片、模型请求失败／超时、输出格式错误分别报告。模型原始错误、凭证和本机文件路径不加入模型错误消息；取消后不接受迟到结果，不自动重试。
- 不增加自动裁剪、分块合并、OCR 或新一套 Agent 循环。长图缩放后文字仍可能不清晰，业务规则需要允许“不确定”。
- 每次运行最多 20 次 AI 调用的既有预算保持不变；本轮先验证图片输入，超过预算的批处理策略另行调整。不要将连接检查成功当成识图成功。
