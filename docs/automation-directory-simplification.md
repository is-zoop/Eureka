# 自动化目录精简

2026-10-31：取消“管理应用包”独立页面，等待用户验收。

## 当前入口

| 功能 | 入口 |
| --- | --- |
| 使用应用 | 自动化左侧应用目录 |
| 创建应用 | 去首页创建，在首页使用自动化命令 |
| 导入应用包 | 自动化侧栏标题右侧“…” → 导入应用包 |
| 运行记录、重新读取、查看、AI 修改、导出、启停和卸载 | 左侧对应应用条目的“…”下拉菜单 |
| 清理已安装应用的数据 | 左侧应用“…” → 应用信息 → 文件与数据 |
| 清理卸载后保留的数据 | 设置 → 自动化管理 |

独立包管理页、重复的已安装列表和开发示例下载入口已从界面移除。取消、卸载后返回创建／导入引导页，不恢复旧管理页。没有应用时隐藏常用应用区，并将引导内容放在水平居中、垂直偏上的位置；较矮窗口自动减小上移幅度。侧栏空目录提供带下划线的创建入口；市场应用空目录提供跳转组织市场插件页的入口。开发示例的底层生成器和历史验收资料仍保留供开发使用，不作为正式界面入口。

导入仍先读取声明并展示名称、版本和能力，由用户点击安装。预览及安装均不执行业务脚本；安装继续使用原来的身份、代码摘要和登记修订校验。导入完成后刷新侧栏并打开该应用；取消不安装。使用原有相同应用 ID 时按既有最新版本策略处理，不新增回退入口。

后续应用包导出已改为系统“另存为”选择路径，不再直接落到默认下载位置，且不添加成功提示；见[保存路径验收](./automation-save-as.md)。

卸载后保留数据使用设置公共模板展示。清理只针对用户选中的已卸载应用，先显示确认；提交携带用户、登录代次、应用 ID 和 revision 0。若该应用已被重新安装，服务器拒绝旧的清理请求，要求刷新。正常界面移除不会删除任何代码包、浏览器登录或用户数据。

2026-11-03：卸载、清理数据和相关安装确认统一使用组件库 Dialog。卸载默认保留数据，可勾选“同时删除用户数据”，提交必须确认同一应用 ID，仅清理当前账号的应用数据及创作工作区，不清理宿主浏览器登录或模型凭证。仍在运行的应用不能清理；组织插件在其他安装范围仍有登记时拒绝删除共享数据，并保留原安装。清理失败时显示实际警告，不宣称数据已删除。

## 用户验收

本次仅修改界面和文档，无新增原生改动。重启 `E:\Eureka` 的开发服务并刷新即可；前一轮浏览环境编辑所需的原生编译仍按该轮说明完成。

1. 打开自动化，确认“管理应用包”按钮、重复列表、开发示例下载已消失；现有应用仍能从侧栏打开和运行。
2. 点击侧栏标题右侧“…” → 导入应用包，选择已有 ZIP，确认出现安装预览；取消不安装，确认后应用显示在侧栏并打开运行页。无应用的空目录也能导入。
3. 导入错误或无效 ZIP 时在弹窗显示实际原因，可以重新选择；不自动重试安装。运行期间导入菜单暂不可用。
4. 原运行页的更多操作已移到左侧应用条目的“…”菜单，仍可导出、启用／停用、查看信息、用 AI 修改和卸载；原生受控运行期间不允许打开菜单中断执行。
5. 打开设置 → 自动化管理，确认之前的卸载残留记录仍在。用测试数据验证取消和确认清理，其他应用、浏览器登录不受影响。若没有残留，显示空状态。
6. 用同一测试应用验证卸载保留数据、重新安装复用数据；不要在日常应用上验证不可撤销清理。
