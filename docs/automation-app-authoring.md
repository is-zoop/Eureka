## 用户现在怎样创建

1. 首页新对话选择“自动化”，或输入 `/automation`，直接描述实际需求。
2. 原有 Pi loop 读取任务和宿主 SDK，按需要探索网页或询问业务问题。需要网页时在**当前首页对话右侧**打开原生浏览器。
3. 登录、验证码、文件选择、首次网页变更授权由用户处理；AI 继续执行观察、读取和方法探索。无需用户再操作一遍录制。
4. AI 生成完整的独立 JavaScript 应用包、参数界面、动态流程和必要的 AI 规则；应用包尚未加入目录。
5. AI 用私有测试参数实际试运行，宿主比较真实输出、产物或所选文件的实际内容。生成、运行、校验分别报告，失败不能显示通过。
6. 原对话显示应用名称、版本、参数、实际支持范围、限制和校验项。通过后，用户点击“保存到自动化目录”。对话保持原位，提供“查看自动化”；保存完成后退出创建模式。
7. 从自动化目录配置并使用应用，查看实际执行画布、日志、结果和下载。目录里的“用 AI 修改为新版本”会打开首页新任务，关联原应用版本，不改正在运行的旧版本。

创建对话中没有执行画布。创建卡片只呈现必要配置、授权、试运行结果和保存入口，复用现有参数组件、登录澄清卡片与授权组件。应用运行画布仍在自动化目录。

## 建议按顺序验收

### 1. 无网页的纯脚本应用

首页新对话选择“自动化”，发送：

> 创建一个接收文本列表的工具：去掉空项和重复项，按字母排序，返回结果并导出 JSON。先用 pear、apple、pear、空项验证，预期为 apple、pear。后续我会换列表重复使用。不要把这组测试数据写进代码默认值。

应出现真实的任务读取、代码生成、试运行与校验工具调用，而不是“当前只支持需求确认”。卡片应区分“代码已生成”“实际试运行”“结果校验”，通过时保存按钮可用。

保存后应满足：

- 当前对话保留，创建模式结束；普通问题不再获得创建工具。
- 点击“查看自动化”进入侧边栏对应应用，显示公共配置与动态执行画布。
- 输入另一组文本，结果随参数变化；节点数量来自应用声明，不固定四个。
- 查看应用详情代码路径：代码位于正式 `plugins/automation/<用户>/<应用ID>/<版本>/`，没有为此工具新增 Eureka 业务页面。

### 2. 不同网页字段

可先用本机模拟网页验证链路：

> 打开 http://127.0.0.1:8080/automation-app-demo.html?view=marketing ，查询 DEMO-001 和 DEMO-002，读取标识、名称、营销编号、费率、日期、标签和附加对象。生成可更换查询标识的工具。你自己观察页面、执行查询、保存方法证据并校验；我只处理登录和必要确认。

检查浏览器是否打开在**首页对话**右侧；应由 AI 实际观察、定义查询动作、执行并提取字段，不要求用户重复录制。营销编号保留文本，费率零保留为 0，列表与对象不压成一段描述。

校验需要本任务宿主实际读取／表格提取的证据，并覆盖应用声明的结果列。无需第二个不同商品编号，不使用商品价格／销量专用编译器。

再用你自己的商品页或另一业务页面测试，同样由 AI 探索并生成不同包；这一步由你操作验证，开发者没有访问真实业务网站。

### 3. 真实文件处理

准备一个专门的业务测试文件夹，避免拿重要文件作首次写入试验。示例需求：

> 创建文本文件清理工具：读取我选择的 TXT，去掉空行和重复行，再写入我选择的输出目录，保留原文件。生成清理结果文件并核对实际内容。

生成候选界面后，在对话配置卡片用系统选择器选择输入文件与输出目录，明确输出目录的写入权限，保存本机配置，再在原对话告诉 AI“已选择，继续”。

- AI 的文件探索工具只读已经选择并保存的配置项，不接受任意绝对路径。
- 文件写入验证需要实际文件或产物内容，单纯返回 `{success:true}` 不算通过。
- 改了代码后，旧文件授权不自动扩大到新代码；相同代码只调整私有校验参数可以继续使用原授权。
- 保存应用只复制发布代码，首次在正式目录使用时按需重新配置、选择文件。测试配置与授权不会被迁移进代码包。

### 4. 脚本加 AI 判断

> 创建一个工具：输入文本列表，逐条用 AI 判断是咨询还是投诉，输出原文和分类，并导出 JSON。分类只允许这两个值；请把判断放进明确的 AI 节点，其他步骤用脚本。

应生成 `ai/rules.json` 和实际的 AI 流程节点。运行使用当前用户已配置的默认可用模型；应用没有模型密钥。实际 AI 输出需要符合声明的数据结构和选项，否则失败，不猜测类别、不给后续网页动作传入未验证输出。AI 节点没有执行工具，不会重新探索整个网页。

AI 分类的正确性仍受具体规则与模型影响，校验仅证明本次输入满足声明检查；不声称所有未知输入都正确。

图片判断已补充正式图片输入：优先传已授权文件引用，宿主复用 Pi 的图片缩放处理，并发送图片消息。兼容已有草稿的 `input.image={mediaType,base64}`，图片不再占用文字的 64,000 字节限额。格式、大小、授权、默认模型识图能力和输出结构分别检查；详情和用户验收见 [自动化 AI 图片节点](./automation-ai-images.md)。

### 5. 修改版本与失败分支

| 操作 | 预期 |
| --- | --- |
| 在已保存应用当前版本点“用 AI 修改为新版本” | 首页新对话关联原版本，读取原发布代码，保留应用 ID 与名称，生成新版本 |
| 新版试运行通过后保存 | 正式目录增加版本，用户数据保留；旧运行固定原版本，不被覆盖 |
| 同版本换代码或使用另一个任务的证据 | 宿主拒绝，不显示通过 |
| 校验字段缺失、数字格式不符、结果不一致 | 显示具体未通过的校验项，保存按钮不可用 |
| 运行还在等待登录／授权 | 不标记通过；AI 等待同一运行，不创建另一次查询 |
| 变更或文件写入结果未知／失败 | 停止当前创建操作，需要用户明确继续，不自动修改后重放同一变更 |
| 切换对话、隐藏网页、弹窗或刷新 | 保留任务及运行；需要网页时等待连接／展示恢复，只继续原运行允许派发的步骤，不重放结果未知的操作 |
| 主动停止、退出创建模式或拒绝授权 | 取消所属任务；刷新或切页不自动恢复已取消的操作 |
| 保存时响应丢失，刷新或重复点击 | 已保存记录恢复为“查看自动化”，不重新运行或覆盖其他包 |
| 在普通聊天发送非自动化问题 | 仍使用原会话能力，不因历史里有创建过程就开放创建工具 |

### 6. 隐私和兼容性

运行后从正式应用页导出 ZIP。只应有发布清单中的代码、UI、流程、规则、资源和说明，不包含真实测试输入、配置、账号、浏览器资料、授权、运行日志、探索证据或结果。

应用导入另一个用户环境后使用自己的配置、登录和模型凭证。原商品查询工具、A03 文件清单、A04 模拟网页应用、普通聊天和 Skill／HTTP MCP 企业扩展继续按原方式使用。

## 实现边界与数据位置

- 复用 `useAgentSession`、原有 Pi loop、会话队列、澄清、SSE 与权限设置。创建工具仅在绑定任务的运行中临时激活，恢复普通聊天后撤销；“全部工具关闭”仍阻止创建。
- 创建任务绑定用户、Haze 登录代次、来源会话和原版本。工作区位于 `app-data/<用户>/creation/<任务ID>/`，候选代码及试运行的内部登记也位于该工作区的 `runtime/` 内；未保存候选不出现在正式应用目录。
- 真实业务方法证据、测试参数、预期结果、校验记录、临时授权及产物都留在用户数据目录。发布时按清单读取不可变包，不压缩整个工作区，不安装第三方依赖。
- 生成器检查显式样本长编号、账号标记、凭证字面量和本地绝对路径等常见误入代码的情况；这不是能识别所有隐私内容的审查器。发布包仍需按实际共享范围查看内容，Haze 上传不在本轮自动执行。
- 网页探索使用固定 DOM 观察器，提供有界文本、控件语义定位和表格结构；网页文本作为证据，不当作系统指令。不开放任意网页 JavaScript、Cookie、签名或通用桌面控制。
- 浏览器适配边界沿用 A04：顶层可见 DOM；跨域 iframe、闭合 Shadow DOM、纯画布或要求可信原生输入的网站可能需要后续适配。失败说明实际阶段，不强制把所有网站套成商品模板。
- AI 节点通过宿主现有模型能力执行明确规则；只允许声明的节点调用，单轮最多 20 次，无自动重试，取消后不接受迟到结果。模型原始错误和密钥不返回应用代码。
- 校验是对当前代码、当前输入、当前按钮与声明检查的确定性比较；没有执行的分支不标成功。通过一次不等于所有未知输入已经验收。
- Haze 自动化应用分发、Python 适配和其他桌面软件的窗口／鼠标／键盘控制仍在本轮范围之外。
