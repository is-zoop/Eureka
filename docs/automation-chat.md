# 从首页对话调用自动化应用

2026-11-03：源码接入、v0.84 聊天网页连接／分轮卡片修复及 v0.85 显式再次运行，等待用户验收；未运行编译、类型检查、测试、模型调用或真实业务执行。

## 使用方式

1. 首页输入框打开添加命令菜单，或输入 `/` 搜索应用名称。
2. “插件”分组同时提供当前用户的“我的应用”和当前项目可用的已安装市场自动化应用。市场应用保留组织插件图标，本地应用用自动化图标。菜单读取声明，不运行应用代码。
3. 选中应用后显示可移除的插件标签，继续用自然语言说明参数和运行需求。标签在后续消息中保留，便于查询同一次运行；移除标签后不再为新消息开放该应用的执行能力。
4. AI 在原 Pi loop 中调用已保存应用，不重新生成代码或探索网站。参数不完整时先澄清；文件、目录必须在对话运行卡片的“配置”中选择。已经保存且仍有效的个人配置和授权可以复用。
5. 可以由 AI 根据用户明确的运行指令启动，也可以在卡片确认配置后点“开始运行”。两种入口复用同一个运行 ID，不会各执行一次。
6. 对话里的卡片复用 `AutomationApplication`，包含原有配置、动态画布、日志、结果、下载、登录／人工验证和网页变更授权。网页在当前对话右侧打开，仍由原生浏览器桥接执行。
7. AI 可查询该次真实运行的状态／结果，也可按用户指令停止。较大的结果提示在卡片查看／下载，不省略后冒充完整结果。运行结束后可在原卡片点击“再次运行”，或在对话提出新的运行请求；不会自动重试。

现有 `/automation`／“自动化”命令仍表示“创建新应用”。选已保存应用表示“运行现有应用”，两者不会混用。创建模式和计划模式中不调用已保存应用，退出后再选择应用命令。

## 执行和数据边界

- 继续使用同一 Pi loop 和现有 `startAppRun` 等运行接口，不注册新的聊天循环、不通过 Shell 或任意 HTTP 绕过应用运行器。
- 聊天能力只在当前请求实际选择了应用且工具权限未全部关闭时临时开放；结束后撤销。工具执行再次核对当前任务的选择、用户、安装版本、摘要和启用状态，不能凭历史聊天获得另一应用的执行权限。
- 普通 Skill／MCP 插件保留原选择校验与调用方式；市场页面仍统一展示为插件类型，不新增安装或更新流程。
- 使用调用者自己的配置、浏览器账号、文件授权和模型凭证。调用记录只放在 `app-data/<用户>/chat-automation/<会话ID>/`，不进入发布包。
- 每个逻辑请求固定应用版本引用和运行 ID。同一请求重试或响应丢失时恢复该次运行；等待文件选择、登录或授权不创建替代运行。一个会话同时控制一个在途调用，另一次运行需等待或先停止；历史卡片可同时保留。
- 刷新和切页只断开显示与轮询，不调用停止接口。聊天显式停止和运行卡片停止按钮可以停止所属运行；真实错误、进程退出和身份／授权失效仍按现有规则报告。
- 历史运行不会因为刷新自动重跑。登录或应用版本变化后需重新选择应用，不自动套用旧参数启动。
- 每次调用通过持久化工具结果中的 invocationId 关联原对话，卡片位于对应轮次的回复下方。调用新应用时默认展开新卡片、折叠之前的卡片，点击标题可重新展开；后续状态查询不复制或移动原卡片。兼容旧结果 JSON，新结果同时写入结构化引用。
- 会话统一轮询发现调用，并为当前可见分支的在途调用提供唯一浏览器连接；折叠卡片、滚出可见区域或加载旧历史不会释放其他卡片的浏览器。聊天和自动化目录的连接随页面切换交接，不同时争用网页。

## v0.84 原因与修复

- 首页浏览器此前只接受创建任务的 `applicationTaskId`，保存应用运行使用 `applicationRunId`，导致连接服务已等待但右侧原生面板没有显示。现同时支持两种引用，并限定聊天连接只在首页负责控制，目录继续使用原桥接。
- 原运行卡片只读取会话最新记录，并固定放在消息列表末尾。现按每次调用返回所有记录，将卡片插在对应对话轮次末尾；单个已卸载应用读取失败不影响其他历史卡片。
- 卡片继续复用 `AutomationApplication` 与组件库的折叠组件，不建立第二套运行器，也不通过折叠、刷新触发重跑。

## v0.85 失败后再次运行

- 原对话卡片将已建立的运行统一锁定，失败后按钮也不可点击。现结束状态（失败、停止、中断及完成）均可由用户点击“再次运行”。执行中继续显示停止按钮。
- 复用卡片当前配置与已有授权，新建运行 ID，原失败日志和结果保留在目录运行记录。原对话卡片及 AI 状态读取跟随本次最新运行。
- 再次运行先持久化分配引用，再使用原运行接口启动；同一旧运行的并发点击、准备响应丢失均复用同一新引用。启动响应不确定时仍“确认原启动”，不会另起一次。刷新、折叠、状态查询均不会触发重试。

## 用户验收

本轮没有修改原生桌面代码。请自行重启原来的开发服务并刷新 Eureka，保证现有会话加载新执行工具；无需重新编译 Tauri。

1. 搜索你已保存的“文件夹图片尺码表智能识别应用”，确认能在插件命令中选择；再确认已安装市场应用也可搜索，图标保留。
2. 先选一个简单、方便核对的应用。说明参数并要求运行；在卡片配置中确认或选择文件，检查对话卡片与目录运行页使用同一套组件。选命令本身不应执行代码。
3. 图片应用按少量已知图片验收；网页版应用按原有登录／授权验收，确认网页打开在首页右侧，并且等待时不重复启动。
4. 在应用运行中刷新、切到自动化目录再返回，同一次运行 ID 和步骤应保留；原目录里能找到相同运行。
5. 运行结束后问“查看这次结果”，应查询原运行；问“重新运行一次”才建立新的调用。出现失败或不确定的网页变更时，不应自动重试。
6. 关闭全部工具，或移除已选应用标签后发送普通消息，不应继续获得该应用的运行能力。更新／停用／卸载市场插件或换账号后，旧选择应被拒绝。
7. 确认 Atlas 等普通插件、普通聊天和“自动化”创建命令保留原行为。
8. 同一会话先准备或完成尺码图应用，再调用商品查询应用。确认第一张卡片留在尺码图回复下且自动折叠，第二张位于商品查询回复下且展开；手动展开旧卡片，内容仍属于原应用、原运行。
9. 商品查询运行时折叠卡片、上下滚动、加载旧消息，确认右侧网页仍可连接。刷新后确认卡片位置、原运行 ID 保留；询问旧运行状态不应在最新回复下复制一张旧卡片。
10. 先在聊天运行网页应用，再切目录和返回首页，检查只有当前页面负责网页控制；登录或授权仍在原共用组件处理。若旧失败运行已终止，请明确发起一次新的运行，旧失败不会自动重跑。
11. 打开截图中的失败卡片，确认按钮变为“再次运行”；可先修改配置再点击。新运行的状态、画布、日志及右侧网页应对应新任务，原失败记录仍在运行记录中。快速重复点击不应产生两次新运行；刷新后应恢复这次新运行，而不是自动再跑。
12. 通知（v0.86）：打开已有失败／已停止的运行，切到其他会话再返回、折叠展开卡片、切目录及刷新，均不应重弹历史错误。主动停止只更新状态和日志；实际运行中新发生的失败或异常中断仍提醒一次，另一新运行即使原因相同也可正常提醒。
