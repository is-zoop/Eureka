# 首页对话调用自动化（v0.89）

2026-11-05：v0.89 源码已调整，等待用户验收。未运行编译、类型检查、测试、模型或真实业务自动化。本轮重启服务并刷新即可；此前 v0.88 的 Rust／Tauri 多任务页面改动若尚未编译，仍需按 [浏览器任务页面验收](./browser-task-pages.md)处理。

## 多任务网页（v0.88）

不同会话／任务在同一浏览器环境中打开各自的页面，共享登录，不再因为另一个内部任务使用此环境而报占用。切回未结束任务恢复原页面，显示恢复本身不重复查询。聊天运行的临时工作区和运行租约也按运行分开；配置、登录及授权仍归当前用户。右侧一次展示一个页面，非展示任务保留状态并等待可见网页连接，未开放隐藏网页并行操作。完整编译与验收步骤见上面的文档。

## 当前交互

v0.89：同一应用可包含多个独立功能。`inspect` 返回 `actions` 的名称、说明、参数、流程和输出；后续按 `actionId` 准备配置和运行，不能将另一功能的输入、节点或结果套用到本次调用。各功能保存的配置和文件授权独立，网页环境仍共用应用设置。详见 [多功能应用](./automation-multiple-functions.md)。本轮无新增 Rust 改动，未执行编译或测试。

1. 从首页命令菜单选择已保存应用，描述任务。
2. AI 用同一个 Pi loop 读取应用声明、已保存配置和流程。聊天不显示运行卡片、配置面板或画布，也没有需要用户点击的运行按钮。
3. 普通参数通过工具配置；用户明确要求执行且配置完整后，AI 直接启动并逐步调度。
4. 遇到登录、验证码、问题或首次网页变更授权，通过现有澄清卡片等待用户。新增文件／目录授权显示简洁的选择按钮，选择后自动续接原任务。网页仍在首页右侧原生浏览器打开。
5. 每步返回真实状态、输入和输出。AI 根据原脚本实际可执行的下一步继续，最终汇总结果并提供产物下载链接。
6. 自动化目录继续保留完整配置、画布、日志和运行记录；从目录启动的应用仍连续执行。

本版取代 v0.83～v0.86 的“聊天展示运行卡片／手动点击运行／卡片折叠”交互。创建新应用仍使用原有 `/automation` 任务及生成预览，本轮只改变已保存应用的聊天调用方式。

## 配置规则

- `inspect`／`prepare` 返回字段声明、当前默认配置、临时覆盖、缺失参数及流程，不执行业务代码。
- `configure` 仅修改声明的字段，检查文本、数字、布尔、日期、对象、列表等类型。未提供字段保持原值。
- `persist:false` 是本次任务覆盖；启动时冻结为该运行的输入，不写回默认配置。
- 用户明确要求“以后都用／保存默认”时才 `persist:true`，使用读取时的 `configRevision` 做版本检查，只保存用户要求的字段。
- 文件字段不接受 AI 提供的路径或伪造授权。`choose_file` 绑定字段、读／读写范围及是否保存默认，由用户通过选择器授权；已保存且有效的授权直接复用。
- 运行输入已经固定后不修改正在执行的参数。保存新的默认值不会改变已启动脚本的输入。

## 工具和逐步运行

仍使用 `eureka_automation_run`，通过 mode 调用不同能力：

| mode | 行为 |
| --- | --- |
| inspect／prepare | 查看声明、已保存配置、当前运行及实际流程 |
| configure | 配置本次输入或保存指定默认字段 |
| choose_file | 请求用户选择并授权一个文件或目录 |
| start | 直接启动，默认采用逐步调度 |
| next | 使用返回的 stepToken 放行一个真实主步骤 |
| status | 等待、读取同一次运行，不重发动作 |
| value | 按真实输出引用、字段路径及分页读取大结果 |
| restart | 用户明确重试后创建新运行，保留旧记录和本次参数 |
| stop | 停止当前运行及未执行的步骤 |

- 插件的 `ctx.step` 在主步骤开始前等待宿主放行，worker 中的变量、浏览器、分支和循环保留。同一个步骤令牌重复提交不会执行两次。
- 下一步来自脚本实际排队的步骤，不按画布名称猜测，不允许跳过尚未完成的主步骤。嵌套子步骤随所属主步骤执行；循环再次进入同一节点会生成新的执行序号和令牌。
- 一个长步骤尚未完成时使用 `status` 等待；不得用 `start` 或新运行来“推进”。步骤失败、结果未知或等待用户时，不自动重复动作。
- 步骤输入／输出和产物使用原运行日志及文件引用；较大值明确返回引用和分页信息，不截断后冒充完整结果。
- 应用代码应将文件、网页、AI、提问、产物等 SDK 业务操作放入 `ctx.step`。新生成应用的开发约定已同步。主步骤外的 SDK 业务调用在逐步模式下会报告兼容原因。
- 非规范旧脚本可明确选择 `executionMode:whole` 继续整流程调用；不能静默将失败运行切为整流程并重放。目录运行方式不受此选项影响。

## 等待、恢复和数据

- 应用提问与网页授权转换为原会话的持久澄清组。只有实际用户回答能传回运行器；AI 不能通过参数批准网页操作。自定义／跳过回答不等于授权。
- 文件选择后，宿主保存授权并提交澄清回答；原 Pi loop 自动续接。取消澄清会清理所属交互并停止正在等待的应用，不影响普通会话的问题处理。
- 刷新、切页、读取状态不推进步骤、不重跑，也不取消运行。浏览器连接继续由会话级宿主管理，独立于聊天可见组件。
- 服务／工作进程退出后按原规则标记中断，不恢复已经消失的脚本闭包或自动重复网页变更。
- 用户配置、授权、交互、日志和实际产物继续只在用户数据目录；应用包不携带创建者信息。普通插件、安装管理、创建模式和目录运行器沿用原能力。
- 聊天产物链接复用保存路径选择，取消保存保持静默。

## 用户验收

请自行重启原开发服务并刷新 Eureka，无需重新编译 Tauri。

1. 选择一个已经配置好的本地文件应用，说“使用已保存配置运行”。确认没有运行卡片，也不用点击运行；处理详情中能看到 inspect／start／next 等工具调用，并返回真实结果。
2. 说“这次把某参数改为 X 后运行”，完成后去目录检查默认配置未变；再说“以后默认使用 Y”，检查只保存所要求的配置字段。
3. 选择未配置文件的应用，要求执行。应出现文件选择请求；选择后自动继续，取消不执行，也不将 AI 提供的路径直接当作授权。
4. 运行网页应用：已登录时复用；需要登录时在右侧完成并回答澄清。首次网页变更只在用户明确允许后执行，拒绝则停止，后续同范围复用原授权。
5. 在处理详情／目录运行记录检查节点：一个 next 对应一个主步骤；循环执行序号真实增加，分支只记录实际路径。长步骤查询状态、刷新或恢复连接不会重复提交。
6. 运行中切目录再回首页、刷新，再说“继续原任务”。确认使用原运行 ID；业务失败后不自动重试，明确要求“再次运行”才创建新运行。
7. 下载生成的 CSV／JSON，确认出现保存路径选择；检查另一应用、普通聊天及目录中直接运行仍正常。
8. 对旧脚本的兼容提示，先确认步骤包装；只有明确选择整流程兼容执行时才按原方法执行，不以“修复”名义自动重放失败操作。
